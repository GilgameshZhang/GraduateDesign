# 打印段同机器优化变异说明

## 📝 新增功能概述

在原有变异策略基础上，新增了针对**同一台打印机上的打印件**的局部优化变异操作。

### 核心思想

传统的打印段变异是随机交换任意两个打印件（可能在不同的打印机上），而新的同机器优化变异是：
1. **识别同一台打印机上的所有打印件**
2. **对它们进行局部顺序优化**
3. **三种优化策略**：交换、2-opt、插入

这种方式更加**精细化**，因为同一台打印机上的打印顺序优化不会影响机器分配，只会调整打印顺序，从而可能：
- 减少等待时间
- 优化批次安排
- 提高打印效率

## 🎯 四种打印段局部优化操作

### 1️⃣ 同机器任意交换 (sameMachineSwap)

**操作**：随机选择同一台打印机上的两个打印件，交换它们的位置。

**示例**：
```
打印机2上的打印件: [工件0, 工件3, 工件1, 工件4]
位置索引:         [  2,     5,     7,     9  ]

随机选择位置2和7进行交换

结果: [工件1, 工件3, 工件0, 工件4]
```

**代码逻辑**：
```java
// 只交换OS，MS保持不变（因为都在同一台打印机上）
int tempOS = chromosome.gene_OS[pos1];
chromosome.gene_OS[pos1] = chromosome.gene_OS[pos2];
chromosome.gene_OS[pos2] = tempOS;
```

**关键点**：
- ✅ 只交换OS（工件编号）
- ✅ MS不变（因为都是同一台打印机）
- ✅ 保持打印机分配不变

### 2️⃣ 同机器2-opt交换 (sameMachine2Opt)

**操作**：随机选择同一台打印机上的一个子序列，反转该子序列。

**什么是2-opt？**
```
原序列: [A, B, C, D, E, F]
选择子序列[B, C, D, E]（位置1-4）
反转子序列: [A, E, D, C, B, F]
```

**示例**：
```
打印机2上的打印件: [工件0, 工件3, 工件1, 工件4, 工件2]
位置索引:         [  2,     5,     7,     9,    11 ]

随机选择idx1=1, idx2=3（对应位置5和9）
反转子序列[工件3, 工件1, 工件4]

结果: [工件0, 工件4, 工件1, 工件3, 工件2]
```

**代码逻辑**：
```java
// 反转positions[idx1...idx2]之间的OS
while (idx1 < idx2) {
    int pos1 = positions.get(idx1);
    int pos2 = positions.get(idx2);
    
    int tempOS = chromosome.gene_OS[pos1];
    chromosome.gene_OS[pos1] = chromosome.gene_OS[pos2];
    chromosome.gene_OS[pos2] = tempOS;
    
    idx1++;
    idx2--;
}
```

**优势**：
- ✅ 2-opt是TSP问题的经典优化方法
- ✅ 可以消除"交叉"路径
- ✅ 适合优化打印顺序

### 3️⃣ 同机器插入操作 (sameMachineInsert)

**操作**：随机选择一个打印件，将其从当前位置移除，插入到另一个位置。

**示例**：
```
打印机2上的打印件: [工件0, 工件3, 工件1, 工件4]
位置索引:         [  2,     5,     7,     9  ]

移除位置5的工件3，插入到位置9之后

步骤1：移除工件3
  [工件0, _, 工件1, 工件4]

步骤2：左移后面的元素
  [工件0, 工件1, 工件4, _]

步骤3：在位置9插入工件3
  [工件0, 工件1, 工件4, 工件3]
```

**代码逻辑**：
```java
if (removePos < insertPos) {
    // 向右插入：左移[removePos+1, insertPos]的元素
    for (int i = removePos; i < insertPos; i++) {
        chromosome.gene_OS[i] = chromosome.gene_OS[i + 1];
    }
    chromosome.gene_OS[insertPos] = removedJob;
} else {
    // 向左插入：右移[insertPos, removePos-1]的元素
    for (int i = removePos; i > insertPos; i--) {
        chromosome.gene_OS[i] = chromosome.gene_OS[i - 1];
    }
    chromosome.gene_OS[insertPos] = removedJob;
}
```

**优势**：
- ✅ 比交换更灵活
- ✅ 可以将一个工件"插队"到前面或后面
- ✅ 适合优化紧急订单或大件/小件的顺序

## 🔄 完整的识别和操作流程

### 主方法: mutatePrintSameMachineOptimization

```java
输入：染色体

步骤1：识别每台打印机上的打印件
  打印机1: [工件0, 工件2]      → 2个打印件 ✓
  打印机2: [工件1, 工件3, 工件4] → 3个打印件 ✓
  打印机3: [工件5]             → 1个打印件 ✗（不足2个）

步骤2：过滤出有效的打印机（至少2个打印件）
  有效打印机: [打印机1, 打印机2]

步骤3：随机选择一台打印机
  选择：打印机2

步骤4：随机选择一种操作类型
  选择：2-opt（反转子序列）

步骤5：执行操作
  原: [工件1, 工件3, 工件4]
  反转[工件3, 工件4]: [工件1, 工件4, 工件3]

输出：变异后的染色体
```

### 辅助方法: groupPrintJobsByMachine

```java
输入：染色体，jobCount

逻辑：
  遍历打印段（前jobCount个元素）：
    位置i的打印机 = gene_MS[i]
    位置i的工件   = gene_OS[i]
    
    将位置i添加到打印机的位置列表中

输出：Map<打印机编号, 位置列表>

示例：
  gene_OS = [0, 1, 2, 3, 4]
  gene_MS = [1, 2, 1, 2, 3]
  
  输出：
    打印机1 → [0, 2]      (工件0和2)
    打印机2 → [1, 3]      (工件1和3)
    打印机3 → [4]         (工件4)
```

## 📊 整合到变异策略

### 修改后的Mutation方法

```java
// 现在有4种变异类型（原来是3种）
int mutationType = r.nextInt(4);

switch (mutationType) {
    case 0:
        // 打印段OS交换（跨机器）
        mutatePrintSequenceSwap(candidate);
        break;
    case 1:
        // 离散段OS交换
        mutateDiscreteSequenceSwap(candidate);
        break;
    case 2:
        // MS机器重分配
        mutateMachineAssignment(candidate);
        break;
    case 3:
        // 同机器打印件优化 ← 新增！
        mutatePrintSameMachineOptimization(candidate);
        break;
}
```

### 变异类型对比

| 类型 | 作用域 | OS变化 | MS变化 | 适用场景 |
|------|--------|--------|--------|---------|
| **打印段OS交换** | 跨机器 | ✓ | ✓ | 调整机器负载均衡 |
| **离散段OS交换** | 离散工序 | ✓ | ✗ | 调整加工顺序 |
| **MS机器重分配** | 任意 | ✗ | ✓ | 更换机器分配 |
| **同机器打印优化** | 同一台打印机 | ✓ | ✗ | 优化打印顺序 |

## ✅ 优势分析

### 1. 精细化搜索

```
传统变异：
  工件0在打印机1，工件1在打印机2
  交换后：工件0在打印机2，工件1在打印机1
  → 改变了机器分配

同机器优化：
  工件0、工件1都在打印机1
  交换后：工件0、工件1仍在打印机1，但顺序不同
  → 只改变打印顺序，不改变机器分配
```

**好处**：
- 搜索空间更小，更容易找到局部最优
- 不破坏机器负载均衡
- 专注于打印顺序优化

### 2. 多样化的邻域操作

```
交换：适合小范围调整
2-opt：适合消除"交叉"顺序
插入：适合大范围调整（将一个工件移到前面或后面）
```

**效果**：
- 不同操作覆盖不同的邻域结构
- 增加搜索的多样性
- 提高找到最优解的概率

### 3. 自动过滤无效操作

```java
if (validMachines.isEmpty()) {
    return;  // 没有打印机有2个及以上的打印件
}
```

**好处**：
- 避免对只有1个打印件的打印机进行无意义操作
- 提高变异的有效性

## ⚠️ 注意事项

### 1. 适用条件

```
该变异操作要求：
- 至少有一台打印机上有2个及以上的打印件
- 如果所有打印机都只有1个打印件，该操作会直接返回
```

### 2. 计算成本

```

```
