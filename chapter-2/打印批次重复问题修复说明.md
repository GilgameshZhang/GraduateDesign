# 打印批次重复问题修复说明

## 📅 修复日期
2025-12-18

## 🐛 问题描述

**现象**：
- 最后输出solution时，打印机的打印批次存在大量重复
- 例如：本应该只有4个批次，但显示了12个批次
- 多出来的8个批次是前4个批次的重复

**示例**：
```
预期输出：
打印机1: [批次1, 批次2, 批次3, 批次4]

实际输出：
打印机1: [批次1, 批次2, 批次3, 批次4,   ← 第1次evaluate添加
         批次1, 批次2, 批次3, 批次4,   ← 第2次evaluate重复添加
         批次1, 批次2, 批次3, 批次4]   ← 第3次evaluate重复添加
```

## 🔍 问题根源分析

### 问题代码（修复前）

**文件**：`chapter-2/src/main/java/ProblemFrame/CaculateFitness.java`

```java
public double evaluate(Chromosome chromosome, Problem input, Operation[][] operationMatrix) {
    // ...
    
    // 问题1: 只在printSolution为null时初始化
    if (chromosome.printSolution == null) {
        chromosome.printSolution = new List[machineCount];
        for (int i = 0; i < machineCount; i++) {
            chromosome.printSolution[i] = new ArrayList<>();
        }
    }
    // 如果printSolution已经存在，不会清空！
    
    // ...
    
    // 处理每台打印机
    for (Map.Entry<Integer, List<Integer>> entry : machineMap.entrySet()) {
        // ...
        solutions = tabuSearch.solve();
        
        // 问题2: 使用addAll追加，而不是替换
        chromosome.printSolution[machineIndex].addAll(solutions);  // ❌ 累积添加
        // ...
    }
}
```

### 问题原因

1. **printSolution不会被清空**
   ```java
   if (chromosome.printSolution == null) {
       // 只在null时初始化
       chromosome.printSolution = new List[machineCount];
   }
   ```
   - 第一次evaluate：`printSolution == null`，初始化新数组
   - 第二次evaluate：`printSolution != null`，跳过初始化，使用旧数据
   - 结果：旧数据被保留

2. **使用addAll追加而不是替换**
   ```java
   chromosome.printSolution[machineIndex].addAll(solutions);
   ```
   - `addAll`是追加操作，不会清空原有内容
   - 每次evaluate都追加一次
   - 结果：批次累积重复

### 问题场景

**场景1：精英染色体多次evaluate**
```java
// GA.java中
Chromosome best = ...;

// 第1次：更新best时evaluate
if (best.fitness < currentBest.fitness) {
    best = new Chromosome(currentBest);
    // best.printSolution已有数据
}

// 第2次：每代结束时可能再次evaluate
c.evaluate(best, input, tempOpMatrix);
// → printSolution追加，变成2倍

// 第3次：最后输出时再次evaluate
c.evaluate(best, input, operationMatrix);
// → printSolution追加，变成3倍
```

**场景2：可视化时evaluate**
```java
// 最后输出
c.evaluate(best, input, operationMatrix);  // 生成operationMatrix用于输出

// 生成可视化
visualizer.generateAllCharts(outputDir);  // 使用printSolution

// 如果之前已经evaluate过2次，此时printSolution已经是3倍数据
```

## ✅ 修复方案

### 修复代码

```java
public double evaluate(Chromosome chromosome, Problem input, Operation[][] operationMatrix) {
    // ...
    
    initOperationMatrix(operationMatrix);
    
    // 修复：每次evaluate都重新初始化printSolution，避免重复累积
    chromosome.printSolution = new List[machineCount];
    for (int i = 0; i < machineCount; i++) {
        chromosome.printSolution[i] = new ArrayList<>();
    }
    // ✓ 不再检查null，每次都清空重建
    
    // ...
}
```

### 修复原理

1. **每次都重新初始化**
   - 不再检查`printSolution == null`
   - 每次evaluate都创建新的数组
   - 清空所有旧数据

2. **保证数据新鲜**
   - 每次evaluate的结果都是当前这次计算的
   - 不会累积历史数据
   - 避免重复

3. **与当前策略一致**
   - 根据之前的讨论，不复用装箱结果
   - 每次都重新运行禁忌搜索
   - printSolution也应该每次重新生成

## 💡 为什么这样修复是正确的？

### 1. 符合当前策略

根据之前的讨论：
- **不复用已有的装箱方案**
- **每次evaluate都重新运行禁忌搜索**

因此：
- printSolution也应该每次重新生成
- 不应该保留旧数据

### 2. 保证数据一致性

```java
evaluate(chromosome) {
    // 清空所有旧数据
    chromosome.printSolution = new List[...];
    
    // 重新计算所有机器的批次
    for (machine : machines) {
        solutions = tabuSearch.solve();  // 重新计算
        printSolution[machine].addAll(solutions);  // 添加新数据
    }
    
    // 结果：printSolution完全反映本次evaluate的结果
}
```

### 3. 避免状态累积

**修复前的问题**：
- 染色体像是有"记忆"的，记住了之前所有evaluate的结果
- 导致数据越来越多

**修复后**：
- 染色体是"无记忆"的，每次evaluate都是全新的
- 数据始终是最新的、唯一的

## 📝 其他相关问题

### 如果需要复用装箱方案呢？

如果将来想要复用已有的装箱方案（避免重复计算），应该：

1. **不要每次都清空**
   ```java
   // 检查是否已有有效的装箱方案
   if (chromosome.printSolution == null || !isValid(chromosome.printSolution)) {
       // 只在没有或无效时重新初始化
       chromosome.printSolution = new List[machineCount];
       // ...
   }
   ```

2. **在添加前清空单个机器**
   ```java
   // 清空当前机器的旧数据
   chromosome.printSolution[machineIndex].clear();
   // 添加新数据
   chromosome.printSolution[machineIndex].addAll(solutions);
   ```

3. **使用标志位**
   ```java
   boolean needRecalculate = ...;
   if (needRecalculate) {
       chromosome.printSolution = new List[machineCount];
       // ...
   }
   ```

但**当前策略是不复用**，所以每次清空是正确的。

### 深拷贝问题

在`Chromosome`的拷贝构造函数中有深拷贝printSolution的代码：

```java
if (c.printSolution != null) {
    this.printSolution = new List[c.printSolution.length];
    for (int i = 0; i < c.printSolution.length; i++) {
        if (c.printSolution[i] != null) {
            this.printSolution[i] = new ArrayList<>(c.printSolution[i]);
        }
    }
}
```

现在每次evaluate都清空，这个深拷贝的作用减小了，但保留它也无害。
