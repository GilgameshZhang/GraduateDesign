# 关键路径和关键块判断逻辑修复说明

## 问题诊断

在检查关键路径和关键块的判断逻辑时，发现`findOperationPosition`方法**没有适配新的编码方式**，导致无法正确找到工序在gene_OS中的位置。

## 核心问题

### 旧代码的错误逻辑

```java
// ❌ 错误：直接比较MS中的值和机器编号
if (count == discreteOperCount && ms[i] == machineNo + 1) {
    return i;
}
```

**问题分析：**
1. 在新编码方式下，离散工序的`ms[i]`存储的是**相对索引**（1-based），不是绝对机器编号
2. `machineNo`来自`Operation`对象，是实际的机器编号（1-based）
3. `ms[i] == machineNo + 1`这个比较毫无意义，永远无法正确匹配

### 编码方式回顾

**新的离散工序MS编码：**
- **固定顺序**：按(工件0工序2, 工件0工序3, ..., 工件1工序2, ...)排列
- **相对索引**：存储的是该工序在其可选机器列表中的相对位置（1-based）
- **解码需求**：需要通过proDesMatrix找到可选机器列表，再用相对索引获取实际机器编号

## 修复方案

### 新的findOperationPosition方法

完全重写，正确处理新编码方式：

```java
/**
 * 在gene_OS中找到指定工序的位置（适配新编码方式）
 * 
 * 新编码方式：离散工序的MS使用相对索引（固定顺序），需要通过解码来验证机器编号
 */
private int findOperationPosition(Operation op, int[] os, int[] ms, int jobCount) {
    int jobNo = op.jobNo;
    int targetMachineNo = op.machineNo;  // 实际机器编号（1-based）
    int operNo = op.task;  // 工序编号
    
    if (operNo < 2) {
        return -1;  // 只处理离散工序
    }
    
    // 步骤1：计算该工序是该工件的第几个离散工序（0-based）
    int discreteOperIndex = operNo - 2;
    
    // 步骤2：在OS中找到该工件的第discreteOperIndex次出现（在离散段）
    int count = 0;
    int positionInOS = -1;
    for (int i = jobCount; i < os.length; i++) {
        if (os[i] == jobNo) {
            if (count == discreteOperIndex) {
                positionInOS = i;
                break;
            }
            count++;
        }
    }
    
    if (positionInOS == -1) {
        return -1;  // 未找到
    }
    
    // 步骤3：验证机器编号 - 从MS的相对索引解码出实际机器编号
    // 3.1 计算MS中的固定位置
    int msIndex = jobCount;
    for (int j = 0; j < jobNo; j++) {
        msIndex += (input.getOperationCountArr()[j] - 2);
    }
    msIndex += discreteOperIndex;
    
    // 3.2 获取相对索引
    int relativeIndex = ms[msIndex];
    
    // 3.3 根据相对索引获取实际机器编号
    int[][] operationToIndex = input.getOperationToIndex();
    double[][] proDesMatrix = input.getProDesMatrix();
    int operIdx = operationToIndex[jobNo][operNo];
    
    // 3.4 找到可选机器列表
    List<Integer> availableMachines = new ArrayList<>();
    for (int k = 0; k < proDesMatrix[operIdx].length; k++) {
        if (proDesMatrix[operIdx][k] > 0 && proDesMatrix[operIdx][k] != Double.MAX_VALUE) {
            availableMachines.add(k + 1);  // 1-based
        }
    }
    
    // 3.5 验证相对索引是否有效
    if (relativeIndex < 1 || relativeIndex > availableMachines.size()) {
        return -1;  // 相对索引无效
    }
    
    // 3.6 获取实际机器编号
    int actualMachineNo = availableMachines.get(relativeIndex - 1);
    
    // 步骤4：验证机器编号是否匹配
    if (actualMachineNo == targetMachineNo) {
        return positionInOS;
    }
    
    return -1;  // 机器编号不匹配
}
```

## 工作流程示例

假设要找工件2的工序3在gene_OS中的位置：

```
Operation对象：{jobNo=2, task=3, machineNo=5}

步骤1：计算离散工序索引
discreteOperIndex = 3 - 2 = 1  (第2个离散工序，0-based)

步骤2：在OS中查找
OS: [0, 1, 2, 3, 4, | 1, 0, 2, 1, 3, 0, 2, ...]
         打印段      |    离散段
找到工件2在离散段的出现：位置7（第1次），位置11（第2次）
discreteOperIndex=1 → 返回位置11

步骤3：验证机器编号
3.1 计算MS固定位置
msIndex = 5 + (工件0离散数) + (工件1离散数) + 1
        = 5 + 2 + 3 + 1 = 11

3.2 获取相对索引
MS[11] = 2  (相对索引)

3.3 获取可选机器列表
proDesMatrix[工件2工序3] = [0, 8, 0, 10, 12, 0, ...]
可选机器 = [M2(8ms), M4(10ms), M5(12ms)]

3.4 解码实际机器
relativeIndex = 2 → availableMachines[1] = M4

3.5 验证
actualMachineNo = 4 ≠ targetMachineNo = 5
→ 返回-1（不匹配）

如果MS[11] = 3，则：
relativeIndex = 3 → availableMachines[2] = M5
actualMachineNo = 5 == targetMachineNo = 5
→ 返回位置11（匹配！）
```

## 影响范围

   - `identifyCriticalBlocks` 调用 `findOperationPosition`

   - 交换操作将作用于正确的位置

   - `identifyCriticalPath` 本身不受影响（它使用operationMatrix）
