🐛 问题1：NullPointerException - printSolution未初始化
═══════════════════════════════════════════════════════════════════════════

【错误信息】
java.lang.NullPointerException
    at ProblemFrame.CaculateFitness.evaluate(CaculateFitness.java:118)

【原因】
Chromosome.printSolution 数组在创建时未初始化。

【修复方案】
1. Chromosome.java 构造函数：设置 printSolution = null
2. CaculateFitness.java evaluate() 开始处：添加初始化逻辑

【修复代码】
if (chromosome.printSolution == null) {
    chromosome.printSolution = new List[machineCount];
    for (int i = 0; i < machineCount; i++) {
        chromosome.printSolution[i] = new ArrayList<>();
    }
}

🐛 问题2：ArrayIndexOutOfBoundsException - operNoOfEachJob多次递增
═══════════════════════════════════════════════════════════════════════════

【错误信息】
java.lang.ArrayIndexOutOfBoundsException: 3
    at ProblemFrame.CaculateFitness.evaluate(CaculateFitness.java:190)

【原因】
operNoOfEachJob 被错误地多次递增，导致工序索引超出范围。

【具体问题】
1. 第93行：统计阶段错误递增 operNoOfEachJob[jobNo]++
2. 第119行：装箱阶段错误递增 operNoOfEachJob[jobNo]++
3. 第149行：赋值阶段才递增 operNoOfEachJob[jobNo]++

结果：同一个工序的operNoOfEachJob被增加了3次！

【修复方案】
1. 统计阶段：只统计，不递增
2. 装箱阶段：只准备数据，不递增
3. 赋值阶段：先获取当前值，然后递增

🐛 问题3：变量名错误 - machineNo vs minIndex
═══════════════════════════════════════════════════════════════════════════

【位置】批处理阶段时间更新（第184-185行）

【错误代码】
machTimes[machineNo].remove(size - 1);
machTimes[machineNo].addAll(size - 1, t);

【正确代码】
machTimes[minIndex].remove(size - 1);
machTimes[minIndex].addAll(size - 1, t);

【原因】
批处理阶段选择了minIndex机器，但更新时间段时错误使用了machineNo。

🐛 问题4：ArrayIndexOutOfBoundsException - getMachineNoAndTime索引错误
═══════════════════════════════════════════════════════════════════════════

【错误信息】
java.lang.ArrayIndexOutOfBoundsException: 5
    at ProblemFrame.CaculateFitness.getMachineNoAndTime(CaculateFitness.java:30)

【原因】
proDesMatrix 索引使用错误：
- MS[i] 是选择的备选机器索引（1-based）
- 应该用 MS[i]-1 来索引 proDesMatrix

【修复方案】
int selectedMachineIndex = MS[i] - 1;
machineNoAndTimeArr[1] = proDesMatrix[totaloperNo][selectedMachineIndex];

📊 问题5：算例数据格式错误
═══════════════════════════════════════════════════════════════════════════

【原因】
重新生成的算例中，每道工序只有1台备选机器，但Chromosome生成时可能选择索引1，
而数组长度只有1（索引0），导致越界。

【修复方案】
简化算例格式，确保每道工序只有1台备选机器，这样MS[i]只能是1，索引就是0。
