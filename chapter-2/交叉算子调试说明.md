# 交叉算子-1值调试说明

## 🐛 现象

交叉后打印段出现-1值：

```
交叉前-父代0: OS=[4,1,2,0,3,4,2,3,0,1], MS=[2,2,2,2,1,1,2,1,2,1]
交叉前-母代1: OS=[3,1,0,4,2,3,1,2,4,0], MS=[1,2,1,2,2,2,2,1,2,1]

交叉后：
❌ 错误：打印段位置1的工件编号无效: -1
❌ 错误：打印段位置2的工件编号无效: -1
❌ 错误：打印段位置4的工件编号无效: -1
```

## 🔬 分析示例

### 场景1：jobSet1包含大部分工件

```
jobCount = 5
jobSet1 = {0, 2, 3, 4}  (4个工件，90%)
jobSet2 = {1}  (1个工件)

父代1: [0, 1, 2, 3, 4]
父代2: [4, 3, 2, 1, 0]

POX步骤1：保留jobSet1
o1 = [0, -1, 2, 3, 4]  (保留0,2,3,4)
p1 = [-1, 1, -1, -1, -1]  (只剩工件1)

o2 = [4, 3, 2, -1, 0]  (保留4,3,2,0)
p2 = [-1, -1, -1, 1, -1]  (只剩工件1)

POX步骤2：填充
填充o1[1]: 从p2找非-1
  index2 = 0: p2[0] = -1, skip
  index2 = 1: p2[1] = -1, skip
  index2 = 2: p2[2] = -1, skip
  index2 = 3: p2[3] = 1, o1[1] = 1 ✓

填充o2[3]: 从p1找非-1
  index1 = 0: p1[0] = -1, skip
  index1 = 1: p1[1] = 1, o2[3] = 1 ✓

结果：应该没有-1！
```

### 场景2：jobSet1和实际位置不匹配

如果出现-1，可能是因为：

1. **工件重复**：父代中同一个工件出现多次
   ```
   父代: [0, 1, 1, 2, 3]  ← 工件1出现两次！
   ```

2. **工件缺失**：父代中缺少某个工件
   ```
   父代: [0, 1, 2, 2, 3]  ← 缺少工件4！
   ```

3. **逻辑错误**：填充时跳过了某些位置

## 💡 可能的问题和解决方案

### 问题1：父代本身就有问题

**症状**：父代OS中有重复或缺失的工件

**解决**：在初始化或修复方法中确保OS的有效性

### 问题2：交叉逻辑错误

**症状**：POX/JBX的填充逻辑有漏洞

**解决**：重写填充逻辑，确保所有位置都能填充

### 问题3：边界条件处理不当

**症状**：特定的jobSet1组合导致问题

**解决**：添加特殊情况处理
