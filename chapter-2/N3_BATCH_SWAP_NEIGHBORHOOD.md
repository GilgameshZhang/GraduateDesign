# N3 邻域动作：相邻批次交换 (Adjacent Batch Swap)

## 时间
2025-12-19

## 动作描述

**N3 邻域动作**专注于优化同一台打印机上的批次执行顺序，通过交换相邻两个打印批次的顺序来改进 makespan。

---

## 一、动作定义

### 基本概念

- **批次（Batch）**：在同一台打印机上、同一时刻开始打印的一组零件
- **相邻批次**：在同一台打印机上，执行顺序相邻的两个批次
- **批次交换**：改变两个相邻批次的执行顺序，但批次内部结构（零件组成、零件顺序、机器分配）保持不变

### 约束条件

✅ **允许的操作**：
- 交换同一台打印机上的相邻批次
- 批次A和批次B的顺序从 [A, B] 变为 [B, A]

❌ **不允许的操作**：
- 交换非相邻批次（如跳过中间批次）
- 修改批次内部的零件组成
- 修改批次内部的零件顺序
- 跨打印机交换批次

## 二、实现原理

### 1. 数据结构

#### BatchSwapMove 类
```java
private static class BatchSwapMove {
    List<Integer> batch1Positions;  // 批次1的零件在gene_OS中的位置
    List<Integer> batch2Positions;  // 批次2的零件在gene_OS中的位置
    int[] originalOS;               // 原始gene_OS（用于撤销）
    int[] originalMS;               // 原始gene_MS（用于撤销）
}
```

### 2. 核心算法

#### 生成候选移动
```java
private List<BatchSwapMove> generateMovesN3(Chromosome chromosome, int maxCandidates)
```

**步骤**:
```
1. 遍历每台打印机 m
   │
   ├─ 获取该机器的批次列表 batches[m]
   │
   ├─ 如果 batches[m].size() < 2，跳过（无法交换）
   │
   └─ 遍历相邻批次对 (batch_i, batch_{i+1})
      │
      ├─ 收集 batch_i 中所有零件在 gene_OS 中的位置
      │  （零件编号从 batch_i.placeItemList 获取）
      │
      ├─ 收集 batch_{i+1} 中所有零件在 gene_OS 中的位置
      │
      └─ 创建 BatchSwapMove(positions_i, positions_{i+1})
```

#### 应用批次交换
```java
private void applyBatchSwap(Chromosome chromosome, BatchSwapMove move)
```

**步骤**:
```
1. 保存原始 gene_OS 和 gene_MS
   │
2. 提取批次1的所有 (零件, 机器) 对
   │
3. 提取批次2的所有 (零件, 机器) 对
   │
4. 合并所有位置并排序
   │
5. 重新写入：先放批次2，再放批次1
   │
   例如：
   原序列: [J0, J1, J2, J3, J4]  (J0,J1是批次1, J2,J3,J4是批次2)
   交换后: [J2, J3, J4, J0, J1]  (批次2在前，批次1在后)
   │
6. 清空 printSolution（需要重新装箱）
```

#### 撤销批次交换
```java
private void undoBatchSwap(Chromosome chromosome, BatchSwapMove move)
```

**步骤**:
```
1. 从 move.originalOS 恢复 gene_OS
2. 从 move.originalMS 恢复 gene_MS
3. 清空 printSolution
```

## 三、为什么需要 N3？

### 问题场景

在某些情况下，批次的执行顺序会显著影响 makespan：

#### 场景 1：后续工序等待

```
打印机 M1:
  批次1: [J0, J1]  打印时间 = 10h
  批次2: [J2]      打印时间 = 5h

如果 J2 的后续离散工序非常紧急，
而 J0, J1 的后续工序不紧急，
则应该先打印批次2，让 J2 尽早进入后续工序。

交换前: [J0, J1] → [J2]
        |--------10h--------|---5h---|
        
交换后: [J2] → [J0, J1]
        |---5h---|--------10h--------|
        
J2 可以提前 10h 进入后续工序！
```

#### 场景 2：打印高度依赖

```
打印机 M1:
  批次1: 高度 = 50mm  打印时间 = 8h
  批次2: 高度 = 20mm  打印时间 = 3h

如果批次2的零件更关键（在关键路径上），
先打印批次2可以减少总 makespan。
```

### N3 的优势

✅ **细粒度优化**：N1/N2 只能在机器间移动零件，N3 可以优化同机器内的批次顺序  
✅ **保持装箱结构**：不破坏已优化的装箱方案，只调整顺序  
✅ **计算开销小**：批次交换是 O(n) 操作，比重新装箱快很多  
✅ **互补性强**：与 N1/N2 结合使用，可以覆盖更多优化空间

## 六、性能考虑

### 时间复杂度

- **生成候选**: O(m × b × j)
  - m = 打印机数量
  - b = 平均每台机器的批次数
  - j = 平均每个批次的零件数

- **应用交换**: O(j)
  - j = 两个批次的总零件数

- **撤销交换**: O(n)
  - n = gene_OS 的长度（需要复制整个数组）

### 优化建议

✅ **限制候选数**：每次生成最多 5 个批次交换候选（比 N1/N2 少）  
✅ **优先选择**：优先尝试批次数量差异大的机器  
✅ **早期停止**：如果连续多个候选都无改进，提前结束

## 九、常见问题

### Q1: 为什么只交换相邻批次？
**A**: 
- 约束合理：相邻批次的交换更可能改进解（依赖关系更强）
- 减少搜索空间：避免评估太多无效候选
- 符合实际：在实际生产中，相邻批次的调整更灵活

### Q2: 如果批次交换后装箱结果完全不同怎么办？
**A**: 
- 批次交换只改变零件在 gene_OS 中的顺序
- 重新 evaluate 时，装箱算法会根据新顺序重新装箱
- 这正是我们想要的：通过顺序调整来影响装箱结果

### Q3: N3 会增加多少计算时间？
**A**: 
- 候选数少（5个），计算开销小
- 如果迭代20步，N3 大约占 20/3 ≈ 7 次（与 N1、N2 轮换）
- 预计增加总时间 10-15%，但换来更好的解质量

### Q4: 可以交换非相邻批次吗？
**A**: 
- 理论上可以，但需要修改代码
- 建议先测试相邻批次交换的效果
- 如果效果好，再考虑扩展到非相邻批次
