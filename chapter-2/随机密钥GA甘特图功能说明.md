## 📊 甘特图内容

### 图表结构

```
机器
  ↑
离散3  │        ┌──J3T2──┐
离散2  │  ┌─J1T3─┐      ┌──J4T2──┐
离散1  │     ┌─J2T2─┐   │
批处理1 │  ┌────────J1T1────────┐┌────J2T1────┐
打印机2 │     ┌──────────J3T0──────────┐
打印机1 │┌─────J1T0─────┐┌─────J2T0─────┐
       └───────────────────────────────────→ 时间
```

### 颜色编码

- 每个零件使用一种颜色
- 同一零件的所有工序颜色相同
- 便于追踪单个零件的加工流程

### 工序标签

- **J0T0**：零件0的打印工序
- **J0T1**：零件0的批处理工序
- **J0T2**：零件0的第1个离散工序
- **J0T3**：零件0的第2个离散工序
- ...

### 机器标签

- **打印机1, 打印机2, ...**：打印阶段
- **批处理1, 批处理2, ...**：批处理阶段（支撑去除等）
- **离散1, 离散2, ...**：离散工序阶段（机加工等）

## 🔍 甘特图解读

### 示例1：正常流程
```
打印机1 │┌─J0T0─┐
批处理1 │   ┌─J0T1─┐
离散1   │      ┌─J0T2─┐
```
**解读**：
- 零件0先在打印机1打印（J0T0）
- 打印完成后进入批处理1（J0T1）
- 批处理完成后进入离散1加工（J0T2）
- 工序之间有等待时间（间隙）说明在排队

### 示例2：排队等待
```
打印机1 │┌─J0T0─┐      ┌─J1T0─┐
批处理1 │   ┌──────J0T1+J1T1──────┐
```
**解读**：
- J0和J1在不同时间打印完成
- 但它们在同一批次中进行批处理
- 批处理矩形很长，包含多个零件

### 示例3：资源竞争
```
离散1   │┌J0T2┐   ┌J2T2┐   ┌J4T2┐
离散1   │     空闲    空闲    空闲
```
**解读**：
- 离散机器1存在空闲时间
- 说明前序工序（批处理）还未完成
- 反映了FCFS策略的特点

## 🔍 甘特图分析要点

### 1. 调度质量分析

**观察指标**：
- ✅ 机器空闲时间：越少越好
- ✅ 工序间隙：反映排队等待
- ✅ 批处理批次：是否充分利用批处理能力
- ✅ 最终完工时间：Makespan值

### 2. 瓶颈识别

**寻找瓶颈**：
```
如果某台机器：
- 工序密集，无空闲 → 可能是瓶颈
- 大量工序排队 → 需要增加该类型机器
- 频繁出现在关键路径上 → 影响Makespan
```

### 3. FCFS策略验证

**验证点**：
- 批处理阶段：先打印完的批次先进入
- 离散工序阶段：先完成批处理的先进入
- 工序顺序：符合FCFS原则

### 4. 对比分析

**混合GA vs 随机密钥GA**：
- 对比同一算例的甘特图
- 观察工序分布差异
- 分析哪种算法的机器利用率更高
- 比较Makespan差异的原因

## 📝 常见问题

### Q1: 甘特图为什么是空的？

**可能原因**：
- Operation矩阵未正确构建
- 工序时间信息缺失

**检查方法**：
```java
// 在detailed_report.txt中查看是否有工序信息
// 确认evaluate()方法正确执行
```

### Q2: 甘特图上的矩形重叠了？

**可能原因**：
- 同一台机器上有工序时间冲突
- FCFS调度逻辑有问题

**解决**：
- 检查评估器中的时间计算
- 验证机器可用时间更新逻辑

### Q3: 如何调整甘特图大小？

**修改方法**：
在 `RandomKeyVisualizer.java` 中：
```java
// 修改这一行的参数
ChartUtils.saveChartAsPNG(new File(outputPath), chart, 1200, 600);
//                                                      ↑宽  ↑高
```
