# 移除禁忌搜索 - 修改总结

## 修改日期
2025-12-18

## 背景

在调试过程中发现，同一个染色体的两次evaluate会得到不同的makespan：
- Fitness反算的makespan: 199916.29
- 重新evaluate的makespan: 206558.29
- 差异: 6642.00 (3.32%)

用户正确指出：**禁忌搜索会保留最优解，理论上不应该越来越差**。

## 问题根源分析

经过深入分析，发现问题不在禁忌搜索本身，而在于：

### 1. 多阶段调度的时间耦合
我们的问题是三阶段流水车间调度：
- 打印 → 批处理 → 离散处理
- 每个工序的开始时间依赖于前一工序的结束时间
- **局部最优（打印时间）≠ 全局最优（整体makespan）**

### 2. 反馈机制破坏幂等性
- 禁忌搜索优化后，结果反馈修改了 `gene_OS`
- 第一次evaluate：基于原始 `gene_OS`
- 第二次evaluate：基于修改后的 `gene_OS`
- 即使使用确定性种子，两次的初始状态已经不同

### 3. 示例说明

```
第一次evaluate：
  打印机1：工件[0,1,2] → 禁忌搜索优化 → [2,0,1]
  反馈修改gene_OS
  批处理队列：J2(50), J0(100), J1(150)
  离散处理：J2选M5 → makespan = 200

第二次evaluate：
  打印机1：工件[2,0,1]（已被修改！）
  种子不同，初始状态不同
  批处理队列顺序可能改变
  离散处理机器选择可能不同 → makespan = 220（变差了！）
```

虽然打印阶段局部优化了，但：
- 改变了批处理的队列顺序
- 影响了离散处理的机器分配
- 整体makespan反而变差

## 解决方案：移除禁忌搜索

基于以上分析，决定移除禁忌搜索，原因：

### 优点
1. ✅ **评估一致性**：同一染色体的fitness总是相同
2. ✅ **代码简洁**：更易理解和维护
3. ✅ **执行速度**：evaluate更快
4. ✅ **稳定性**：避免多阶段耦合的不确定性

### 权衡
⚠️ 装箱质量可能不如禁忌搜索优化，但：
- 遗传算法可以通过足够迭代找到更好的 `gene_OS`
- 整体优化效果更稳定
- 依赖全局搜索而非局部优化

## 总结

这次修改是从"局部优化 + 全局搜索"回归到"纯全局搜索"的策略调整：

- 之前：遗传算法 + 禁忌搜索（局部优化）
- 现在：遗传算法（纯全局搜索） + 天际线装箱（确定性）

**核心目标**：保证fitness评估的**幂等性**和**一致性**，这对遗传算法的正确运行至关重要！
