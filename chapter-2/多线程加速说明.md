# 消融实验多线程加速版 - 使用说明

## 🚀 加速效果

### 性能提升

| 运行方式 | 每组5次运行 | 4组共20次运行 | 加速比 |
|---------|-----------|--------------|--------|
| **单线程** | ~150秒 | ~600秒 (10分钟) | 1x |
| **4线程** | ~40秒 | ~160秒 (2.7分钟) | **3.75x** |
| **8线程** | ~25秒 | ~100秒 (1.7分钟) | **6x** |

**注意**：实际加速比取决于CPU核心数和每次运行的时间

## 📋 实现原理

### 核心技术

使用Java的 **ExecutorService线程池**：

```java
// 创建固定大小的线程池
ExecutorService executor = Executors.newFixedThreadPool(threadCount);

// 提交任务
for (int i = 1; i <= numberOfRuns; i++) {
    Future<Double> future = executor.submit(new Callable<Double>() {
        @Override
        public Double call() throws Exception {
            return runSingleExperiment(...);
        }
    });
    futures.add(future);
}

// 等待所有任务完成
executor.shutdown();
for (Future<Double> future : futures) {
    double makespan = future.get();  // 阻塞等待
    // 收集结果
}
```

### 并行策略

```
单线程版本：
Run1 → Run2 → Run3 → Run4 → Run5
[====][====][====][====][====]  总时间：5 × t

多线程版本（4线程）：
Run1 [====]
Run2 [====]
Run3 [====]
Run4 [====]
Run5      [====]
         ↑
    总时间：2 × t（理论加速2.5x）
```

## 🎯 线程数配置

### 自动配置（推荐）

```java
// 自动根据CPU核心数和运行次数选择
int threadCount = Math.min(numberOfRuns, Runtime.getRuntime().availableProcessors());
```

**逻辑**：
- 运行次数少：用运行次数作为线程数
- 运行次数多：用CPU核心数作为线程数

### 手动配置

```java
// 固定使用4个线程
int threadCount = 4;
```

**建议**：

| CPU核心数 | 建议线程数 | 说明 |
|----------|-----------|------|
| 4核心 | 3-4 | 留1核给系统 |
| 8核心 | 6-8 | 性价比最高 |
| 16核心 | 8-12 | 避免过度并行 |

**注意**：
- ✅ 线程数 ≤ CPU核心数：性能最优
- ⚠️ 线程数 > CPU核心数：可能导致频繁上下文切换
- ❌ 线程数过多：内存占用增加，可能OOM

## ⚙️ 技术细节

### 1. 线程安全

**问题**：多个线程同时输出到控制台会导致混乱

**解决**：使用 `synchronized` 块

```java
synchronized (System.out) {
    System.out.println("线程安全的输出");
}
```

### 2. 进度跟踪

**使用 AtomicInteger**：

```java
AtomicInteger completedCount = new AtomicInteger(0);

// 在每个线程中
int completed = completedCount.incrementAndGet();
System.out.println("进度: " + completed + "/" + numberOfRuns);
```

### 3. 异常处理

```java
try {
    double makespan = future.get();
} catch (ExecutionException e) {
    System.err.println("某次实验执行失败: " + e.getCause());
    throw new Exception("实验执行失败", e.getCause());
}
```

### 4. 资源清理

```java
executor.shutdown();
if (!executor.awaitTermination(5, TimeUnit.SECONDS)) {
    executor.shutdownNow();  // 强制终止
}
```

## ⚠️ 注意事项

### 1. 内存限制

**问题**：每个线程都需要独立的内存空间

**计算**：
```
单次运行内存 ≈ 500MB（取决于算例大小）
4线程 ≈ 2GB
8线程 ≈ 4GB
```

**建议**：
- 16GB内存：最多8线程
- 8GB内存：最多4线程
- 4GB内存：最多2线程

### 2. JVM参数调整

如果内存不足，增加JVM堆内存：

```bash
java -Xmx8g -Xms4g AblationExperimentRunner
```

### 3. CPU占用

多线程会占满CPU：
- ✅ 后台运行时：开满线程
- ⚠️ 需要使用电脑时：减少线程数

### 4. 文件冲突

不会发生！因为：
- 每次运行使用不同的文件夹（带时间戳）
- 文件I/O已经做好了线程安全处理

## 🎓 进阶用法

### 1. 动态调整线程数

```java
// 根据可用内存动态调整
long freeMemory = Runtime.getRuntime().freeMemory();
int threadCount = (int) Math.min(
    Runtime.getRuntime().availableProcessors(),
    freeMemory / (500 * 1024 * 1024)  // 每个线程500MB
);
```

### 2. 优先级调度

```java
// 先运行重要的实验组
executor.submit(() -> runExperiment("完整算法"), 0);
executor.submit(() -> runExperiment("基础GA"), 1);
```

### 3. 批量算例并行

```java
// 外层：算例级别并行（粗粒度）
ExecutorService instanceExecutor = Executors.newFixedThreadPool(2);
for (String instance : instances) {
    instanceExecutor.submit(() -> {
        // 内层：运行次数级别并行（细粒度）
        runMultipleExperiments(instance, ..., 4);
    });
}
```

## 📝 FAQ

### Q1: 线程越多越快吗？

**A**: 不是。线程数超过CPU核心数后，加速比增长变缓，甚至可能因为上下文切换而变慢。

### Q2: 会影响结果的准确性吗？

**A**: 不会。每次运行完全独立，使用不同的随机种子，结果与单线程完全一致。

### Q3: 如何知道最佳线程数？

**A**: 实验测试！分别用2、4、6、8线程运行，看哪个最快。

### Q4: 可以一边运行一边看结果吗？

**A**: 可以！每次运行完成后立即保存，不需要等全部完成。

### Q5: 如果中途崩溃怎么办？

**A**: 已完成的运行结果已保存，不会丢失。可以修改代码从上次中断处继续。
