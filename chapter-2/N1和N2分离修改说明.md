# N1和N2分离修改说明

> 将N1和N2邻域策略独立处理，提高代码可读性和灵活性

---

## 📋 修改概述

将原本合并处理的N1和N2邻域策略分离为独立的代码块，使它们能够独立控制和评估。

---

## 🔧 修改内容

### 修改文件
- **`ChromosomeOperation.java`** - `LocalSearch()` 方法

### 修改前的代码结构

```java
if (neighborhoodType == 0 || neighborhoodType == 1) {
    // N1和N2合并处理

```

## 📊 代码对比

### 修改前（合并处理）

```java
if (neighborhoodType == 0 || neighborhoodType == 1) {
    // 检查N1或N2是否启用
    boolean enableN1 = (params != null) ? params.enableN1 : true;
    boolean enableN2 = (params != null) ? params.enableN2 : true;
    
    // 如果当前邻域被禁用，则跳过
    if ((neighborhoodType == 0 && !enableN1) || (neighborhoodType == 1 && !enableN2)) {
        continue;
    }
    
    // N1 或 N2: 跨机移动（打印段优化）
    List<Move> candidates = new ArrayList<>();
    int n1n2Cand = (params != null) ? params.n1n2Candidates : 10;
    if (neighborhoodType == 0) {
        candidates = generateMovesN1(chromosome, n1n2Cand);
    } else {
        candidates = generateMovesN2(chromosome, n1n2Cand);
    }
    
    // 共用的评估逻辑...
}
```

**问题**：
- ❌ N1和N2耦合在一起
- ❌ 条件判断复杂 `(neighborhoodType == 0 && !enableN1) || ...`
- ❌ 需要在内部再次判断 `if (neighborhoodType == 0)`

---

### 修改后（独立处理）

#### N1 独立代码块

```java
if (neighborhoodType == 0) {
    // N1: 基于打印时间的跨机移动（打印段优化）
    // 检查N1是否启用
    boolean enableN1 = (params != null) ? params.enableN1 : true;
    if (!enableN1) {
        continue;
    }
    
    List<Move> candidates = new ArrayList<>();
    int n1Cand = (params != null) ? params.n1n2Candidates : 10;
    candidates = generateMovesN1(chromosome, n1Cand);
    
    if (!candidates.isEmpty()) {
        Collections.shuffle(candidates);
        
        for (Move move : candidates) {
            applyMove(chromosome, move);
            initOperationMatrix(tempOpMatrix);
            double newMakespan = caculateFitness.evaluate(chromosome, input, tempOpMatrix);
            
            if (newMakespan < currentMakespan) {
                //System.out.println("N1局部搜索有效");
                currentMakespan = newMakespan;
                chromosome.fitness = GA.FITNESS_SCALE / newMakespan;
                improved = true;
                noImprovementCount = 0;
                break;
            } else {
                undoMove(chromosome, move);
            }
        }
    }
}
```

#### N2 独立代码块

```java
else if (neighborhoodType == 1) {
    // N2: 基于面积占用率的跨机移动（打印段优化）
    // 检查N2是否启用
    boolean enableN2 = (params != null) ? params.enableN2 : true;
    if (!enableN2) {
        continue;
    }
    
    List<Move> candidates = new ArrayList<>();
    int n2Cand = (params != null) ? params.n1n2Candidates : 10;
    candidates = generateMovesN2(chromosome, n2Cand);
    
    if (!candidates.isEmpty()) {
        Collections.shuffle(candidates);
        
        for (Move move : candidates) {
            applyMove(chromosome, move);
            initOperationMatrix(tempOpMatrix);
            double newMakespan = caculateFitness.evaluate(chromosome, input, tempOpMatrix);
            
            if (newMakespan < currentMakespan) {
                //System.out.println("N2局部搜索有效");
                currentMakespan = newMakespan;
                chromosome.fitness = GA.FITNESS_SCALE / newMakespan;
                improved = true;
                noImprovementCount = 0;
                break;
            } else {
                undoMove(chromosome, move);
            }
        }
    }
}
```

**优点**：
- ✅ N1和N2完全独立
- ✅ 条件判断简单直接
- ✅ 代码逻辑清晰
- ✅ 便于单独调试和修改

```java
for (int iter = 0; iter < maxIterations; iter++) {
    int neighborhoodType = iter % 5;
    boolean improved = false;
    
    if (neighborhoodType == 0) {
        // N1独立处理
    } else if (neighborhoodType == 1) {
        // N2独立处理
    } else if (neighborhoodType == 2) {
        // N3独立处理
    } else if (neighborhoodType == 3) {
        // N4独立处理
    } else {
        // N5独立处理
    }
    
    if (!improved) {
        noImprovementCount++;
        if (noImprovementCount >= maxNoImprovement) {
            break;
        }
    }
}
```

**统一结构的好处**：

## 🎯 对消融实验的影响

### 1. 更清晰的消融实验
现在可以更直观地理解N1和N2的独立性：

| 实验组 | N1 | N2 | N3 | N4 | N5 |
|--------|----|----|----|----|-----|
| 完整算法 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 无N1 | ✗ | ✓ | ✓ | ✓ | ✓ |
| 无N2 | ✓ | ✗ | ✓ | ✓ | ✓ |

### 2. 更精确的贡献度分析
- N1贡献 = 无N1的性能 - 完整算法的性能
- N2贡献 = 无N2的性能 - 完整算法的性能
- 两者完全独立，不会相互干扰

### 3. 便于调试
- 可以单独调试N1：`params.enableN1 = true; params.enableN2 = false;`
- 可以单独调试N2：`params.enableN1 = false; params.enableN2 = true;`

## 🎓 技术细节

### 代码块独立性
每个邻域策略现在都是一个完整的独立代码块：
1. 检查开关
2. 生成候选
3. 评估候选
4. 应用/撤销移动
5. 更新状态

### 循环结构
```
迭代0: N1 执行
迭代1: N2 执行
迭代2: N3 执行
迭代3: N4 执行
迭代4: N5 执行
迭代5: N1 执行（循环）
...
```

如果某个邻域被禁用，会被跳过（continue），下一次迭代执行下一个邻域。
