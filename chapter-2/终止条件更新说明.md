## 终止逻辑实现

### 代码实现

```java
// 进化循环
int generation = 0;
int stagnantCount = 0;

while (generation < maxGenerations && stagnantCount < maxStagnantGenerations) {
    // 检查时间限制
    long currentTime = System.currentTimeMillis();
    double elapsedMinutes = (currentTime - startTime) / (1000.0 * 60.0);
    if (elapsedMinutes >= params.maxRunTime) {
        printOrWrite("\n达到时间限制(" + params.maxRunTime + "分钟)，算法终止。");
        break;  // 时间到，终止
    }
    
    generation++;
    
    // ... 进化操作 ...
    
    // 更新最优解和停滞计数
    if (population[0].makespan < bestChromosome.makespan) {
        bestChromosome = new RandomKeyChromosome(population[0]);
        stagnantCount = 0;  // 有改进，重置停滞计数
    } else {
        stagnantCount++;    // 无改进，停滞计数+1
    }
    
    // 如果停滞代数达到300，循环自然终止
}
```

### 终止条件判断流程

```
开始迭代
    ↓
每代检查时间 → 时间 ≥ 3分钟？ → 是 → 终止（时间限制）
    ↓ 否
进化操作
    ↓
更新最优解 → 有改进？ → 是 → 重置停滞计数 = 0
    ↓ 否              ↓
停滞计数+1 ← ← ← ← ← ←
    ↓
停滞计数 ≥ 300？ → 是 → 终止（停滞限制）
    ↓ 否
继续下一代
```

## 预期影响

### 1. 运行时间预期

- **时间上限**：不超过3分钟
- **实际情况**：
  - 小算例（J10）：可能1-2分钟就达到300代停滞
  - 中等算例（J20, J50）：可能在2-3分钟内达到停滞
  - 大算例（J100）：更可能触发3分钟时间限制

### 2. 迭代次数预期

- **停滞限制**：300代无改进
- **实际情况**：
  - 种群大小200，每分钟约可迭代30-50代
  - 3分钟约可迭代100-150代
  - 达到300代停滞需要至少300代有记录的迭代

**结论**：大多数情况下，算法会因**时间限制（3分钟）**而终止。

### 3. 对比公平性

| 算法 | 时间限制 | 停滞限制 | 总结 |
|------|----------|----------|------|
| **混合GA** | 3分钟 | 300代无改进 | 主算法 |
| **随机密钥GA** | 3分钟 | 300代无改进 | 对比算法 |

✅ **两种算法使用完全相同的终止条件，对比公平！**
