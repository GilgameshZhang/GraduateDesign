# 变异策略改进说明

## 📝 修改概述

根据用户要求，完全重写了变异操作（Mutation），实现了**多试探选择最优**的变异策略，并添加了**OS层变异**。

## 🎯 新的变异策略

### 核心思想：多试探选择最优

```
对每个染色体：
1. 生成3-5个变异候选
2. 每个候选随机选择一种变异类型
3. 评估所有候选的fitness
4. 选择最优的候选
5. 如果所有候选都不如原染色体 → 不变异（保持原样）
```

### 三种变异类型

#### 1️⃣ 打印段OS交换变异 (mutatePrintSequenceSwap)

```java
// 随机选择打印段的两个位置
int pos1 = r.nextInt(jobCount);
int pos2 = r.nextInt(jobCount);

// 同时交换OS和MS（同步交换）
swap(gene_OS[pos1], gene_OS[pos2]);
swap(gene_MS[pos1], gene_MS[pos2]);
```

**示例**：
```
变异前:
  OS_print = [3, 1, 0, 4, 2]
  MS_print = [2, 1, 1, 2, 1]

随机选择pos1=1, pos2=3

变异后:
  OS_print = [3, 4, 0, 1, 2]  ← 位置1和3交换
  MS_print = [2, 2, 1, 1, 1]  ← 位置1和3同步交换
```

**关键点**：
- ✅ 打印段OS和MS必须同步交换
- ✅ 保持工件和对应打印机的绑定关系

#### 2️⃣ 离散段OS交换变异 (mutateDiscreteSequenceSwap)

```java
// 随机选择离散段的两个位置
int pos1 = jobCount + r.nextInt(discreteLen);
int pos2 = jobCount + r.nextInt(discreteLen);

// 只交换OS，MS不变（MS是固定顺序）
swap(gene_OS[pos1], gene_OS[pos2]);
// gene_MS保持不变
```

**示例**：
```
变异前:
  OS_discrete = [3, 2, 4, 0, 1]  (位置5-9)
  MS_discrete = [2, 1, 1, 1, 2]  (固定顺序，不变)

随机选择pos1=6, pos2=8

变异后:
  OS_discrete = [3, 0, 4, 2, 1]  ← 位置6和8交换
  MS_discrete = [2, 1, 1, 1, 2]  ← MS不变！
```

**关键点**：
- ✅ 离散段MS是固定顺序，与OS解耦
- ✅ 只交换OS，不影响MS

#### 3️⃣ MS机器重分配变异 (mutateMachineAssignment)

保留原有的MS层变异逻辑：

```java
// 随机选择1-3个MS位置
int mutationPoints = 1 + r.nextInt(3);

// 对每个位置：
if (打印工序) {
    // 50%选择层高最高的打印机，50%随机选择
} else if (离散工序) {
    // 50%选择加工时间最短的机器，50%随机选择
}
```

**示例**：
```
选择MS位置: [0, 7, 9]

位置0（打印）: MS[0] = 1 → 2 (层高更高的打印机)
位置7（离散）: MS[7] = 1 → 3 (加工时间最短的机器)
位置9（离散）: MS[9] = 2 → 1 (随机选择)
```

## 🔄 完整的变异流程

### 主方法: Mutation(Chromosome chromosome)

```
输入：原染色体 (fitness = 1000)

步骤1：生成候选 (numCandidates = 3-5)
  候选1: 复制原染色体 → 打印段OS交换 → fitness = 1020 ❌
  候选2: 复制原染色体 → 离散段OS交换 → fitness = 980 ✓
  候选3: 复制原染色体 → MS重分配 → fitness = 1050 ❌
  候选4: 复制原染色体 → 打印段OS交换 → fitness = 990 ✓
  候选5: 复制原染色体 → MS重分配 → fitness = 1010 ❌

步骤2：选择最优候选
  bestFitness = 980 (候选2)

步骤3：应用变异
  if (980 < 1000) ✓
    chromosome ← 候选2
  else
    保持原染色体不变

输出：变异后的染色体 (fitness = 980)
```

### 特殊情况处理

#### 情况1：所有候选都不如原染色体

```
原染色体: fitness = 900 (已经很优)

候选1: fitness = 920 ❌
候选2: fitness = 950 ❌
候选3: fitness = 910 ❌

结果：不变异，保持fitness=900的原染色体
```

#### 情况2：没有fitness计算器

```java
if (caculateFitness == null) {
    mutateSimple(chromosome);  // 退化为简单变异
    return;
}
```

简单变异：随机选择一种变异类型，不评估fitness，直接应用。

## ✅ 优势分析

### 1. 多样性提升

三种变异类型覆盖不同的搜索空间：
- **打印段OS交换**：改变打印顺序和打印机分配
- **离散段OS交换**：改变离散工序加工顺序
- **MS重分配**：改变机器分配（不改变顺序）

### 2. 搜索质量提升

多试探策略确保每次变异都是改进：
- 生成多个候选，选择最优
- 如果都不如原染色体，则不变异
- **避免无效变异，只接受改进**

### 3. 算法鲁棒性

```
好染色体（fitness低）：
  - 多次尝试，难以找到更优 → 很少变异 → 保护精英解

差染色体（fitness高）：
  - 多次尝试，容易找到更优 → 经常变异 → 加速收敛
```

这种**自适应**行为类似于模拟退火的温度机制！

## ⚠️ 注意事项

### 1. 计算成本

```
旧策略：每次变异评估1个染色体
新策略：每次变异评估3-5个染色体

计算量：增加3-5倍
```

**缓解措施**：
- 可以调整`numCandidates`的范围（目前是3-5）
- 可以设置fitness缓存（如果染色体未改变，不重新评估）

### 2. 与局部搜索的关系

新的变异策略本质上是一种**局部搜索**：
- 在当前解的邻域生成多个候选
- 选择最优候选

**建议**：
- 可以考虑减少独立的局部搜索策略（N1-N5）的执行频率
- 或者将变异和局部搜索分开（某些代不做局部搜索，只做变异）

### 3. 参数调优

可调参数：
1. `numCandidates`: 候选数量（目前3-5）
2. `mutationPoints`: MS重分配的点位数（目前1-3）
3. 变异类型选择概率（目前均匀1/3）

**高级改进**：
```java
// 自适应变异类型概率
double[] prob = calculateAdaptiveProbability(generationNo, bestFitness);
int mutationType = selectByProbability(prob);
```
