# 交叉算子分段处理说明

## 🔍 修改内容

将交叉算子分为打印阶段和离散处理阶段两部分，采用不同的交叉策略。

## 📊 修改前后对比

### 修改前（统一处理）

```java
public void Crossover(Chromosome c1, Chromosome c2) {
    // 对整个OS进行POX或JBX交叉
    if (random < 0.5) {
        operSeqCrossoverPOX(c1.gene_OS, c2.gene_OS);
    } else {
        operSeqCrossoverJBX(c1.gene_OS, c2.gene_OS);
    }
    
    // 对整个MS进行两点交换
    machineSeqCrossover_TwoPointSwap(c1.gene_MS, c2.gene_MS);
}
```

**问题**：
1. 打印段和离散段没有区分
2. MS的交叉没有考虑新编码方式（离散段MS是固定顺序的）

### 修改后（分段处理）

```java
public void Crossover(Chromosome c1, Chromosome c2) {
    int jobCount = input.getJobCount();
    
    if (random < 0.5) {
        // POX交叉
        // 打印段：OS和MS同步交叉
        operSeqCrossoverPOX_PrintSync(c1.gene_OS, c1.gene_MS, c2.gene_OS, c2.gene_MS);
        // 离散段：只交叉OS，MS保持不变
        operSeqCrossoverPOX_DiscreteOnly(c1.gene_OS, c2.gene_OS, jobCount);
    } else {
        // JBX交叉
        // 打印段：OS和MS同步交叉
        operSeqCrossoverJBX_PrintSync(c1.gene_OS, c1.gene_MS, c2.gene_OS, c2.gene_MS);
        // 离散段：只交叉OS，MS保持不变
        operSeqCrossoverJBX_DiscreteOnly(c1.gene_OS, c2.gene_OS, jobCount);
    }
}
```

**改进**：
1. ✅ 打印段和离散段分开处理
2. ✅ 打印段OS和MS同步交叉
3. ✅ 离散段只交叉OS，MS保持固定顺序

## 🎯 核心逻辑

### 1. 打印段（前jobCount个元素）

#### OS和MS同步交叉
```
目的：保持工件和其分配的打印机的对应关系

示例（POX）：
父代1：
OS: [0, 1, 2]
MS: [3, 1, 2]

父代2：
OS: [2, 0, 1]
MS: [2, 3, 1]

选择jobSet1 = {0, 2}

子代1：
OS: [0, -, 2]  ← 保留工件0和2
MS: [3, -, 2]  ← 同时保留对应的机器

填充后：
OS: [0, 1, 2]
MS: [3, 1, 2]  ← 工件1从父代2带来机器1
```

#### 为什么同步？
- 打印段的MS直接存储机器编号（1-based）
- MS与OS一一对应：MS[i]是OS[i]工件的打印机
- 交叉时必须保持这种对应关系

### 2. 离散段（jobCount之后）

#### 只交叉OS，MS保持不变
```
目的：只改变工序执行顺序，不改变机器分配

示例（POX）：
父代1离散段：
OS: [0, 1, 2, 0, 1, 2]
MS: [2, 1, 3, 1, 2, 2]  ← 固定顺序的相对索引

父代2离散段：
OS: [1, 0, 2, 1, 0, 2]
MS: [1, 2, 2, 3, 3, 1]  ← 固定顺序的相对索引

选择jobSet1 = {0, 2}

子代1离散段：
OS: [0, -, 2, 0, -, 2]  ← 只交叉OS
MS: [2, 1, 3, 1, 2, 2]  ← MS保持不变！

填充后：
OS: [0, 1, 2, 0, 1, 2]  ← 工序顺序改变了
MS: [2, 1, 3, 1, 2, 2]  ← MS完全不变！
```

#### 为什么MS不变？
- 离散段的MS是固定顺序的相对索引
- MS[jobCount+0] → 工件0工序2的相对索引
- MS[jobCount+1] → 工件0工序3的相对索引
- MS[jobCount+2] → 工件1工序2的相对索引
- ...
- 这个映射是固定的，与OS的排列无关！

/**
 * 打印段POX交叉：OS和MS同步交叉（只作用于前jobCount个元素）
 */
private void operSeqCrossoverPOX_PrintSync(int[] o1, int[] m1, int[] o2, int[] m2) {
    int jobCount = input.getJobCount();
    
    // 1. 随机分配工件集
    List<Integer> jobSet1 = ...;
    
    // 2. 备份打印段（包括OS和MS）
    int[] p1 = 备份o1[0:jobCount];
    int[] pm1 = 备份m1[0:jobCount];
    ...
    
    // 3. 清空打印段
    Arrays.fill(o1, 0, jobCount, -1);
    Arrays.fill(m1, 0, jobCount, -1);
    ...
    
    // 4. 从父代1选择jobSet1的工件（同时移动对应的机器）
    for (int i = 0; i < jobCount; i++) {
        if (jobSet1.contains(p1[i])) {
            o1[i] = p1[i];    // 移动工件
            m1[i] = pm1[i];   // 同时移动机器
            ...
        }
    }
    
    // 5. 填充剩余位置（从父代2取）
    ...
}
```

/**
 * 离散段POX交叉：只交叉OS（从jobCount开始到结束）
 */
private void operSeqCrossoverPOX_DiscreteOnly(int[] o1, int[] o2, int jobCount) {
    int discreteLen = o1.length - jobCount;
    
    // 1. 随机分配工件集
    List<Integer> jobSet1 = ...;
    
    // 2. 备份离散段（只备份OS）
    int[] p1 = 备份o1[jobCount:end];
    int[] p2 = 备份o2[jobCount:end];
    
    // 3. 清空离散段（只清空OS）
    Arrays.fill(o1, jobCount, totalLen, -1);
    Arrays.fill(o2, jobCount, totalLen, -1);
    
    // 4. 从父代1选择jobSet1的工件（只操作OS）
    for (int i = 0; i < discreteLen; i++) {
        if (jobSet1.contains(p1[i])) {
            o1[jobCount + i] = p1[i];  // 只移动工件
            // MS不操作！
            ...
        }
    }
    
    // 5. 填充剩余位置
    // MS完全不参与，保持原样！
    ...
}
```

## 📊 打印段 vs 离散段对比

| 特性 | 打印段 | 离散段 |
|-----|--------|--------|
| OS交叉 | ✓ 参与POX/JBX | ✓ 参与POX/JBX |
| MS交叉 | ✓ 与OS同步交叉 | ✗ 保持不变 |
| MS存储 | 1-based机器编号 | 相对索引（1-based） |
| MS-OS关系 | 一一对应 | 解耦（固定映射） |
| 交叉方法 | _PrintSync | _DiscreteOnly |

## ⚠️ 关键要点

### 1. 为什么打印段同步交叉？

```
打印段MS的语义：MS[i] = 工件OS[i]分配的打印机编号

如果不同步：
父代1: OS=[0], MS=[3]  → 工件0在打印机3
交叉后: OS=[1], MS=[3]  → 工件1在打印机3？

可能的问题：工件1可能放不下打印机3！

同步交叉后：
父代1: OS=[0], MS=[3]
父代2: OS=[1], MS=[1]
子代:  OS=[1], MS=[1]  ← 工件1带着它原本的打印机1
```

### 2. 为什么离散段MS不变？

```
离散段MS的语义：固定位置的相对索引

MS[jobCount+0] = 工件0工序2的相对索引（固定映射）
MS[jobCount+1] = 工件0工序3的相对索引（固定映射）
...

无论OS如何排列，解码时都会：
1. 根据OS[i]的工件号和工序号
2. 计算该工序在MS中的固定位置
3. 从固定位置读取相对索引
4. 解码为实际机器编号

所以OS排列顺序不影响MS的语义！
```

### 3. 与其他操作的配合

| 操作 | 打印段 | 离散段 |
|-----|--------|--------|
| 初始化 | OS随机，MS分配机器 | OS随机，MS固定顺序相对索引 |
| 交叉 | OS和MS同步交叉 | OS交叉，MS不变 |
| 变异 | OS和MS同步变异 | OS和MS独立变异 |
| N4 | - | OS交换，MS不变 |
| N5 | - | OS不变，MS修改 |
| 解码 | MS[i]直接使用 | MS固定位置解码 |
