# 变异操作导致工序-机器错位的问题分析

## 问题现象

虽然修复了POX交叉，但仍然出现[交叉修复]消息：
```
[交叉修复] J16 工序2 机器 M10 → M8
[交叉修复] J16 工序3 机器 M9 → M7
[交叉修复] J13 工序3 机器 M6 → M9
[交叉修复] J13 工序4 机器 M8 → M6
```

## 根本原因：变异操作的致命缺陷

### operSeqMutationSwap 的逻辑

```java
// 随机选择离散段的两个位置
int posa = jobCount + r.nextInt(len - jobCount);
int posb = jobCount + r.nextInt(len - jobCount);

// 交换工序和机器
temp = os[posa];
temp1 = ms[posa];
ms[posa] = ms[posb];    // 交换机器
os[posa] = os[posb];    // 交换工序
os[posb] = temp;
ms[posb] = temp1;
```

### 问题场景

**变异前：**
```
位置35: J13, M9  ← J13的第3次出现 → 工序3
位置40: J13, M6  ← J13的第4次出现 → 工序4
```

**变异后（交换位置35和40）：**
```
位置35: J13, M6  ← J13的第3次出现 → 工序3，但机器是M6（原来是工序4的）❌
位置40: J13, M9  ← J13的第4次出现 → 工序4，但机器是M9（原来是工序3的）❌
```

### 关键问题

**工序编号是根据出现顺序动态计算的：**
```java
// 在evaluate时
int operNo = 2;  // 从工序2开始
for (int j = jobCount; j < i; j++) {
    if (os[j] == jobNo) {
        operNo++;  // 每次出现，工序编号+1
    }
}
```

**变异交换工序后：**
- 位置不变，但工序内容变了
- 工序编号仍然根据位置计算
- 但机器分配已经对应到错误的工序了

### 详细示例

**初始状态：**
```
染色体: [..., J13, J13, J13, J13, ...]
机器:   [..., M7,  M9,  M6,  M8,  ...]
位置:   [..., 35,  40,  45,  50,  ...]

执行时：
位置35: J13第1次出现 → 工序2 → M7 ✓
位置40: J13第2次出现 → 工序3 → M9 ✓
位置45: J13第3次出现 → 工序4 → M6 ✓
位置50: J13第4次出现 → 工序5 → M8 ✓
```

**变异交换位置40和45：**
```
染色体: [..., J13, J13, J13, J13, ...]
机器:   [..., M7,  M6,  M9,  M8,  ...]  ← 交换了M9和M6
位置:   [..., 35,  40,  45,  50,  ...]

执行时：
位置35: J13第1次出现 → 工序2 → M7 ✓
位置40: J13第2次出现 → 工序3 → M6 ❌ (原来工序4的机器)
位置45: J13第3次出现 → 工序4 → M9 ❌ (原来工序3的机器)
位置50: J13第4次出现 → 工序5 → M8 ✓
```

如果工序3不能在M6上加工，就会出现加工时间为0的错误！

## 为什么打印段变异没问题？

```java
private void operPrintSeqMutationSwap(Chromosome chromosome) {
    // 只在打印段内交换
    int posa = r.nextInt(printCount);
    int posb = r.nextInt(printCount);
    // 交换
    geneOs[posa] = geneOs[posb];
    geneMs[posa] = geneMs[posb];
}
```

**打印段每个工件只出现一次：**
- 位置posa: J5, M1 → 工序0 (打印)
- 位置posb: J10, M2 → 工序0 (打印)

交换后：
- 位置posa: J10, M2 → 工序0 (打印) ✓
- 位置posb: J5, M1 → 工序0 (打印) ✓

工序编号始终是0，没有问题！

## 解决方案

### 方案1：限制变异只交换不同工件的工序（推荐）

```java
public void operSeqMutationSwap(Chromosome chromosome) {
    int jobCount = input.getJobCount();
    int[] os = chromosome.gene_OS;
    int[] ms = chromosome.gene_MS;
    int len = os.length;
    
    double posibility = r.nextDouble();
    if (posibility < 0.5) {
        int posa = jobCount + r.nextInt(len - jobCount);
        int posb = jobCount + r.nextInt(len - jobCount);
        
        // 确保两个位置的工件不同
        int maxAttempts = 100;
        int attempts = 0;
        while ((posa == posb || os[posa] == os[posb]) && attempts < maxAttempts) {
            posb = jobCount + r.nextInt(len - jobCount);
            attempts++;
        }
        
        if (attempts >= maxAttempts || os[posa] == os[posb]) {
            return;  // 无法找到不同工件，跳过本次变异
        }
        
        // 交换
        int temp = os[posa];
        int temp1 = ms[posa];
        os[posa] = os[posb];
        ms[posa] = ms[posb];
        os[posb] = temp;
        ms[posb] = temp1;
    }
}
```

### 方案2：交换同一工件的工序时，只改变顺序不改变机器

```java
if (os[posa] == os[posb]) {
    // 同一工件：只交换os，不交换ms
    // 这样只改变调度顺序，不改变机器分配
    int temp = os[posa];
    os[posa] = os[posb];
    os[posb] = temp;
    // ms不变
} else {
    // 不同工件：正常交换
    int temp = os[posa];
    int temp1 = ms[posa];
    os[posa] = os[posb];
    ms[posa] = ms[posb];
    os[posb] = temp;
    ms[posb] = temp1;
}
```

### 方案3：保持现状，依赖修复机制

优点：
- 无需修改变异逻辑
- fixInvalidMachineAssignments会自动修复

缺点：
- 增加计算开销
- 产生的解可能不是最优的变异结果

## 推荐方案

**采用方案1：限制变异只交换不同工件的工序**

理由：
1. **保证可行性**：从源头避免工序-机器错位
2. **保持多样性**：交换不同工件的工序仍然能探索解空间
3. **符合逻辑**：同一工件的工序通常有先后依赖关系，不应随意交换
4. **减少开销**：避免频繁调用修复函数

## 总结

**真正的问题源：**
- ❌ POX交叉（已修复）
- ✅ 变异操作中的工序交换

**问题本质：**
- 离散段中，同一工件出现多次
- 工序编号根据出现顺序计算
- 变异交换位置后，工序编号和机器分配不再对应

**修复效果：**
- 修复前：可能导致程序崩溃或错误结果
- 修复后：fixInvalidMachineAssignments检测并修复错误
- 最优：从源头避免问题（方案1）
