## 两种策略的区别

### 复杂评分策略（useComplexScore = true）

**特点**：
1. **遍历所有未放置的工件**
2. **对每个工件进行 12 级评分**
3. **选择评分最高的工件放置**
4. **如果所有工件都放不下，上移天际线继续尝试**

**优势**：
- 智能选择最优工件
- 批次利用率高
- 解质量好

**示例**：
```
工件序列：[A, B, C, D, E]
当前天际线可以放 C 或 E，C 的评分 = 10，E 的评分 = 8
→ 选择放置 C（评分最高）
```

### 简化策略（useComplexScore = false）

**特点**：
1. **不遍历所有工件**
2. **严格按照输入顺序（counter）尝试放置**
3. **如果当前工件放不下，立即结束当前批次**
4. **开始新批次，继续从当前工件开始**

**特点**：
- 按顺序贪心
- 不跳过工件
- 批次可能更多
- 解质量较差

**示例**：
```
工件序列：[A, B, C, D, E]
当前 counter = 1（指向 B）
如果 B 放不下当前天际线：
→ 立即结束当前批次
→ 开始新批次
→ 继续尝试放置 B（不跳过）
```

## 预期影响

### 性能差异预测

| 配置 | 评分策略 | 预期RPD | 说明 |
|------|---------|---------|------|
| V0-Full | Complex | 0% | 基线 |
| V4-SimpleScore | 按顺序 | +5~10% | 更多批次，利用率下降 |

### 为什么性能会下降？

1. **不能跳过工件**：如果当前工件暂时放不下，不会尝试其他工件
2. **批次数增加**：更容易结束当前批次，导致批次总数增加
3. **空间利用率下降**：无法智能选择最适合的工件填补空隙
4. **顺序依赖性强**：算法性能严重依赖输入顺序

### 实际示例

**复杂评分策略**：
```
批次1: [A, C, E, G]  ← 智能选择，利用率 95%
批次2: [B, D, F]     ← 智能选择，利用率 92%
总批次数: 2
```

**按顺序策略**：
```
批次1: [A, B]        ← B放不下时就结束
批次2: [C]           ← C放不下就结束
批次3: [D, E]        ← E放不下就结束
批次4: [F, G]        
总批次数: 4  ← 更多批次！
```
