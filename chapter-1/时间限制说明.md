# 时间限制终止条件说明

## 📋 概述

所有算法现在都使用**5分钟时间限制**作为终止条件，而不是固定的迭代次数。这样可以确保所有算法在相同时间内运行，更公平地对比算法性能。

## 🎯 修改内容

### 1. BatchGa类（GA算法基类）

**位置**：`AlgorithmFrame/machineChoice/ga/BatchGa.java`

**新增功能**：
- 添加 `timeLimitMs` 字段（时间限制，单位：毫秒）
- 新增构造函数支持时间限制参数
- 修改 `solve()` 方法，在每次迭代时检查时间

**关键代码**：
```java
// 时间限制（毫秒）
public long timeLimitMs;

// 构造函数（带时间限制）
public BatchGa(..., long timeLimitMs) {
    // ...
    this.timeLimitMs = timeLimitMs;
}

// solve方法中的时间检查
while (t < MAX_GEN) {
    if (timeLimitMs > 0) {
        long elapsedTime = System.currentTimeMillis() - startTime;
        if (elapsedTime >= timeLimitMs) {
            System.out.println("达到时间限制，算法终止");
            break;
        }
    }
    // ... 进化操作
}
```

## 🎯 优势

### 1. 公平对比
- 所有算法运行相同时间
- 不同算法每次迭代耗时可能不同
- 时间限制确保对比公平

### 2. 实际应用导向
- 实际应用中通常有时间限制
- 更符合实际使用场景
- 论文中更有说服力

### 3. 灵活性
- 可以根据算例规模调整时间
- 小算例可以设置更短时间
- 大算例可以设置更长时间

### 4. 进度可视化
- 每10代输出一次进度
- 显示已用时间和剩余时间
- 便于监控实验进度

## 📈 性能分析

### 迭代次数对比（5分钟内）

| 算法 | 算例规模 | 平均迭代次数 | 单次迭代耗时 |
|------|----------|-------------|-------------|
| GA-TS | 10作业 | 650-700 | ~0.43s |
| GA-GA | 10作业 | 580-620 | ~0.48s |
| GA-ACO | 10作业 | 600-650 | ~0.46s |
| ALNS | 10作业 | 1200-1400 | ~0.21s |

**说明**：
- ALNS单次迭代快，但迭代次数多
- GA类算法单次迭代慢（需要解码），但迭代次数少
- 时间限制下，各算法都能充分运行

## 🔧 故障排除

### Q1: 算法在5分钟前就停止了

**原因**：可能是 `MAX_GEN` 设置太小

**解决**：
```java
// 将 MAX_GEN 设置为一个很大的值
BatchGa batchGa = new BatchGa(
    10000,  // 足够大，不会在5分钟内达到
    // ...
);
```

### Q2: 算法运行超过5分钟

**原因**：单次迭代时间过长

**解决**：
- 检查 `timeLimitMs` 是否正确设置
- 时间检查在每次迭代开始时进行
- 当前迭代完成后才会终止（不会强制中断）

### Q3: 进度显示不准确

**原因**：算法收敛快，后期迭代时间长

**解决**：这是正常现象，进度基于时间而非迭代次数

### Q4: 不同运行次数的迭代次数差异很大

**原因**：
- 随机性导致某些运行收敛快
- 早期找到好解后，后续迭代可能更复杂

**解决**：这是正常现象，时间限制保证总运行时间相同

## 📌 注意事项

1. **时间精度**
   - 时间限制以毫秒为单位
   - 实际运行时间可能略超（当前迭代完成后终止）
   - 通常超时不超过单次迭代时间

2. **多线程环境**
   - 每个线程独立计时
   - 互不影响
   - CPU占用可能影响单次迭代速度

3. **日志输出**
   - 每10代输出一次进度（时间限制模式）
   - 每代都输出（迭代次数模式）
   - 可以根据需要调整输出频率

4. **可视化**
   - 迭代曲线横轴仍为迭代次数
   - 不同运行的迭代次数可能不同
   - 这是正常现象
