# 多线程实验使用说明

## 概述

第一章现在支持**多线程并行运行**所有实验，大幅提升实验效率！

### 支持的功能

1. ✅ **多算法对比实验**（MultiAlgorithmComparison）
   - GA-TS：外层GA + 内层禁忌搜索
   - GA-GA：外层GA + 内层遗传算法  
   - GA-ACO：外层GA + 内层蚁群算法
   - ALNS：自适应大邻域搜索

2. ✅ **消融实验**（AblationExperimentRunner）
   - 多配置并行运行
   - 自动生成对比报告

3. ✅ **完整可视化**
   - 每次运行都生成图表
   - 迭代曲线、甘特图、批次分布图等

## ⏱️ 重要：时间限制

**所有算法现在使用5分钟时间限制作为终止条件！**

- ✅ 更公平的算法对比
- ✅ 符合实际应用场景
- ✅ 每个算法运行相同时间

如需修改时间限制，请参考 `时间限制说明.md`

## 快速开始

### 1. 多算法对比实验

```java
// 运行: MultiAlgorithmComparison.java
public static void main(String[] args) {
    runMultiAlgorithmComparison(
        "chapter-1/src/main/resources/Machine/machine_2",
        "chapter-1/src/main/resources/PrintItem/printItem_10/printItem_10_01",
        "Small-2M10J",  // 算例名称
        3,              // 每个算法运行3次（每次5分钟）
        true            // 开启可视化
    );
    // 预计耗时：4算法 × 3次 × 5分钟 / 8核 ≈ 7.5分钟
}
```

### 2. 消融实验（多线程版本）

```java
// 运行: AblationExperimentRunner.java
public static void main(String[] args) {
    runAblationExperimentParallel(true);  // 多线程版本
    // 预计耗时：5配置 × 3算例 × 10次 × 5分钟 / 8核 ≈ 47分钟
}
```

## 性能对比

### 单线程 vs 多线程（基于5分钟时间限制）

假设有4个算法，每个运行3次：

| 模式 | 任务数 | 单任务耗时 | 总耗时（4核） | 总耗时（8核） |
|------|--------|-----------|--------------|--------------|
| 单线程 | 12 | 5分钟 | 60分钟 | 60分钟 |
| 多线程 | 12 | 5分钟 | 15分钟 | 7.5分钟 |

**加速比 = CPU核心数（理论上）**

### 实际运行时间估算

| 实验类型 | 配置/算法数 | 算例数 | 运行次数 | 单次时间 | 4核耗时 | 8核耗时 |
|---------|-----------|--------|---------|---------|---------|---------|
| 多算法对比 | 4 | 1 | 3 | 5分钟 | 15分钟 | 7.5分钟 |
| 消融实验 | 5 | 3 | 10 | 5分钟 | 94分钟 | 47分钟 |

**实际加速比取决于CPU核心数！**

## 多算法对比实验详解

### 算法列表

#### 1. GA-TS（您的算法）
- **外层优化**：遗传算法（机器分配）
- **内层优化**：禁忌搜索（作业排序）
- **特点**：双层优化，收敛快

#### 2. GA-GA
- **外层优化**：遗传算法（机器分配）
- **内层优化**：遗传算法（作业排序）
- **特点**：双层进化，探索能力强

#### 3. GA-ACO
- **外层优化**：遗传算法（机器分配）
- **内层优化**：蚁群算法（作业排序）
- **特点**：结合蚂蚁信息素机制

#### 4. ALNS
- **优化方式**：自适应大邻域搜索
- **特点**：单层优化，自适应算子选择

## 调整参数

### 修改线程数

线程数默认为CPU核心数，如需修改：

```java
// 在 runMultiAlgorithmComparison 或 runAblationExperimentParallel 中
int numThreads = 4;  // 手动设置为4个线程
ExecutorService executor = Executors.newFixedThreadPool(numThreads);
```

### 修改运行次数

```java
// 多算法对比
runMultiAlgorithmComparison(
    machinePath, itemPath, instanceName,
    10,     // 改为每个算法运行10次
    true
);

// 消融实验
// 在 runAblationExperimentParallel 中修改
int numRuns = 20;  // 改为每个配置运行20次
```

### 修改算法参数

在 `ExperimentTask.runGA()` 或 `AblationTask.call()` 中：

```java
BatchGa batchGa = new BatchGa(
    1000,   // 增加迭代次数
    200,    // 增加种群规模
    5,      
    2,      
    0.3,    // 调整变异率
    0.9,    // 调整交叉率
    input,
    true,   
    method,
    200,    // 增加内层迭代
    15,     // 增加禁忌表大小
    50      // 增加邻域大小
);
```

## 注意事项

### 1. 内存管理

- 每个线程会占用一定内存
- 建议线程数 ≤ CPU核心数
- 如遇内存不足，减少线程数或运行次数

### 2. 随机种子

- 当前使用：`seed = 12345L + runId`
- 保证每次运行使用不同种子
- 结果可重现（相同runId得到相同结果）

### 3. 系统属性

消融实验使用系统属性传递配置：
```java
System.setProperty("ablation.useHeuristicInit", "true");
```

多线程环境下要注意线程安全！当前实现在每个任务内部设置和清除属性。

### 4. 可视化生成

- 可视化在单线程中生成（避免IO冲突）
- 如不需要可视化，设置 `enableVisualization = false`
- 大量图表会占用较多磁盘空间

### 5. 线程池关闭

```java
executor.shutdown();  // 优雅关闭
// 或
executor.shutdownNow();  // 立即关闭（可能丢失未完成任务）
```

## 故障排除

### Q1: 线程池卡死

**原因**：可能有任务抛出异常导致

**解决**：
```java
try {
    future.get(300, TimeUnit.SECONDS);  // 添加超时
} catch (TimeoutException e) {
    future.cancel(true);
}
```

### Q2: 内存溢出

**原因**：同时运行太多任务

**解决**：
- 减少线程数
- 增加JVM内存：`java -Xmx4g`

### Q3: 结果不一致

**原因**：可能是系统属性冲突

**解决**：
- 使用单线程版本调试
- 检查系统属性设置和清除逻辑

### Q4: 可视化生成失败

**原因**：多线程同时写入同一文件

**解决**：
- 当前版本已在单线程中生成可视化
- 确保输出目录不同

## 进阶使用

### 自定义线程池

```java
// 使用有界队列防止内存溢出
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    4,                          // 核心线程数
    8,                          // 最大线程数
    60L, TimeUnit.SECONDS,      // 线程空闲超时
    new LinkedBlockingQueue<>(100)  // 任务队列大小
);
```

### 添加进度监控

```java
AtomicInteger completedTasks = new AtomicInteger(0);
int totalTasks = configs.size() * instances.size() * numRuns;

// 在每个任务完成后
int completed = completedTasks.incrementAndGet();
System.out.printf("进度: %d/%d (%.1f%%)\n", 
    completed, totalTasks, (completed * 100.0 / totalTasks));
```

### 实时保存中间结果

```java
// 在任务完成后立即保存
synchronized(allResults) {
    allResults.add(result);
    saveIntermediateResult(result);  // 自定义方法
}
```
