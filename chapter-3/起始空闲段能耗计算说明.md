# 起始空闲段能耗计算说明

## 概述

在车间调度中，机器不一定从时间0就开始工作。从时间0到第一个工序开始之间的时间段称为**起始空闲段**。这个时间段也会产生能耗，需要纳入能耗计算和开关机决策。

---

## 问题背景

### 原来的实现
原来的能耗计算只考虑了**工序之间**的空闲间隔：

```
时间轴：
  0.0                    10.0    12.0    15.0    18.0
   |<----未计算---->|<-工序1->|空闲1|<-工序2->|
                           ↑              ↑
                      只计算这些空闲间隔
```

**问题**：时间0到第一个工序开始之间的空闲时间（10.0）**没有计算能耗**！

### 实际情况
在实际生产中：
1. 车间在上班时就会**开启所有机器**（或者机器保持待机状态）
2. 从开始生产到第一个工序分配到该机器之前，机器处于**空闲状态**
3. 这段时间也会产生能耗（待机或开关机）

---

## 修复方案

### 核心思路
在计算每台机器的能耗时，增加**起始空闲段**的处理：

1. **识别起始空闲段**：`initialGap = firstOperation.startTime - 0.0`
2. **纳入开关机决策**：根据空闲长度决定关机还是待机
3. **计算能耗**：计入总的空闲能耗

### 实现代码

```java
// 2. 计算空闲间隔能耗
double idleEnergy = 0.0;
int shutdownCount = 0;
int idleCount = 0;

// 2.1 处理起始空闲段（从时间0到第一个工序开始）
if (!uniqueOperations.isEmpty()) {
    Operation firstOp = uniqueOperations.get(0);
    double initialGap = firstOp.startTime - 0.0;
    
    if (initialGap > 0) {
        // 根据策略计算起始空闲能耗
        double gapEnergy = 0.0;
        if (enableSwitchingStrategy) {
            // 使用开关机策略
            if (params.shouldShutdown(initialGap)) {
                gapEnergy = params.E_switch;  // 关机
                shutdownCount++;
            } else {
                gapEnergy = params.P_idle * initialGap;  // 待机
                idleCount++;
            }
        } else {
            // 强制待机（用于对比实验）
            gapEnergy = params.P_idle * initialGap;
            idleCount++;
        }
        
        idleEnergy += gapEnergy;
        
        if (debugOutput && initialGap > 0.1) {
            System.out.println(String.format("  起始空闲: gap=%.2f, energy=%.4f %s", 
                initialGap, gapEnergy,
                (enableSwitchingStrategy && params.shouldShutdown(initialGap)) ? "(关机)" : "(待机)"));
        }
    }
}

// 2.2 处理工序之间的空闲间隔（原有逻辑）
for (int i = 0; i < uniqueOperations.size() - 1; i++) {
    // ...
}
```

## 开关机决策逻辑

### 决策条件
起始空闲段也遵循相同的开关机决策规则：

```java
// 如果起始空闲时间 >= 预热时间 + 盈亏平衡时间
if (initialGap >= T_warmup + T_breakEven) {
    // 选择关机（更节能）
    energy = E_switch;
} else {
    // 选择待机
    energy = P_idle * initialGap;
}
```

其中：
- `T_breakEven = E_switch / P_idle`（盈亏平衡时间）
- `T_warmup`：机器预热/启动时间

### 示例计算

假设机器参数：
- `P_idle = 0.5 kW`（待机功率）
- `E_switch = 2.0 kWh`（开关机能耗）
- `T_warmup = 1.0 小时`（预热时间）
- `T_breakEven = 2.0 / 0.5 = 4.0 小时`（盈亏平衡时间）

**场景1：起始空闲 = 3.0 小时**
```
initialGap = 3.0 < (1.0 + 4.0) = 5.0
→ 选择待机
→ energy = 0.5 * 3.0 = 1.5 kWh
```

**场景2：起始空闲 = 8.0 小时**
```
initialGap = 8.0 > (1.0 + 4.0) = 5.0
→ 选择关机
→ energy = 2.0 kWh
→ 节能：1.5 kWh（相比待机的 0.5 * 8.0 = 4.0 kWh）
```

## 完整的能耗计算流程

现在，每台机器的能耗计算包括：

### 1. 运行能耗
```
E_run = Σ (P_run * duration)
```

### 2. 起始空闲能耗（新增）
```
if (initialGap > 0) {
    if (shouldShutdown(initialGap)) {
        E_initial = E_switch
    } else {
        E_initial = P_idle * initialGap
    }
}
```

### 3. 工序间空闲能耗
```
for each gap between operations {
    if (shouldShutdown(gap)) {
        E_gap += E_switch
    } else {
        E_gap += P_idle * gap
    }
}
```

### 4. 总能耗
```
E_total = E_run + E_initial + E_gap
```

## 实际案例

### 案例：打印机的能耗计算

假设一台打印机的调度方案：

```
时间轴（小时）：
  0.0        8.0   10.0   12.0        20.0   22.0
   |<-起始空闲->|<-工序1->|<-空闲1->|<-工序2->|
```

**机器参数：**
- `P_run = 5.0 kW`（运行功率）
- `P_idle = 0.5 kW`（待机功率）
- `E_switch = 2.0 kWh`（开关机能耗）
- `T_warmup = 1.0 h`，`T_breakEven = 4.0 h`

**能耗计算：**

1. **运行能耗：**
   ```
   工序1: (10.0 - 8.0) * 5.0 = 10.0 kWh
   工序2: (22.0 - 20.0) * 5.0 = 10.0 kWh
   E_run = 20.0 kWh
   ```

2. **起始空闲能耗：**
   ```
   initialGap = 8.0 h
   8.0 > (1.0 + 4.0) = 5.0 → 关机
   E_initial = 2.0 kWh  ✅ 节能！
   （如果待机：0.5 * 8.0 = 4.0 kWh）
   ```

3. **工序间空闲能耗：**
   ```
   gap1 = 20.0 - 12.0 = 8.0 h
   8.0 > 5.0 → 关机
   E_gap = 2.0 kWh  ✅ 节能！
   （如果待机：0.5 * 8.0 = 4.0 kWh）
   ```

4. **总能耗：**
   ```
   E_total = 20.0 + 2.0 + 2.0 = 24.0 kWh
   
   如果不使用开关机策略：
   E_total = 20.0 + 4.0 + 4.0 = 28.0 kWh
   
   节能：4.0 kWh（14.3%）
   ```

## 对比：有无起始空闲段处理

### 情况1：不计算起始空闲段（旧方法）
```
机器1的能耗：
  运行能耗: 20.0 kWh
  空闲能耗: 2.0 kWh  ← 只计算工序间空闲
  总能耗: 22.0 kWh  ❌ 错误：少算了起始空闲
```

### 情况2：计算起始空闲段（新方法）
```
机器1的能耗：
  运行能耗: 20.0 kWh
  起始空闲: 2.0 kWh  ← 新增
  工序间空闲: 2.0 kWh
  总能耗: 24.0 kWh  ✅ 正确
```

**差异：** 2.0 kWh（起始空闲段的能耗）

## 影响和意义

### 1. 能耗计算更准确
- 考虑了机器从开始到第一个工序之间的能耗
- 更接近实际生产情况

### 2. 优化空间更大
- 算法可以优化工序的开始时间
- 通过延迟或提前开始时间来减少起始空闲

### 3. 开关机策略更合理
- 如果起始空闲很长，可以选择关机节能
- 更真实地反映了实际操作

### 4. 对调度结果的影响
- **紧凑调度**（工序开始时间早）：起始空闲短，能耗可能更低
- **延迟调度**（工序开始时间晚）：起始空闲长，如果关机可能节能

---

## 注意事项

### ⚠️ 假设条件
1. **机器在时间0就处于待机状态**
   - 如果实际情况不同（如机器本来就是关闭的），能耗计算可能不准确
   - 可以通过参数调整来适应不同场景

2. **所有机器同时开始计时**
   - 时间0是统一的基准点
   - 不同机器可能有不同的起始空闲时间

### 💡 扩展可能性
1. **可配置的时间起点**
   - 允许为每台机器设置不同的初始状态
   - 如某些机器在时间0就已经在运行

2. **初始状态参数**
   - 添加 `initialState`（开机/关机/待机）
   - 根据初始状态计算起始能耗
