# 田口实验 - 多线程加速说明

## 🚀 新增功能：多线程并行执行

### 功能概述

田口实验需要运行 **9组×10次=90次** 独立实验，每次实验互不依赖，非常适合并行化。通过多线程可以显著缩短总运行时间。

## 📊 加速效果预估

### 理论加速比

```
加速比 = min(线程数, 任务数) / 1

示例（8核CPU）：
- 单线程: 90次 × 2分钟 = 180分钟 (3小时)
- 8线程:  90次 × 2分钟 / 8 = 22.5分钟
- 理论加速: 8倍
```

### 实际加速比

考虑线程调度、内存竞争等开销，实际加速比约为：

| CPU核心数 | 理论加速比 | 实际加速比 | 预计时间(J20) | 预计时间(J50) |
|-----------|-----------|-----------|--------------|--------------|
| 4核 | 4x | 3.5x | 10分钟 | 25分钟 |
| 8核 | 8x | 6.5x | 5分钟 | 15分钟 |
| 12核 | 12x | 9x | 4分钟 | 10分钟 |
| 16核+ | 16x+ | 11x+ | 3分钟 | 8分钟 |

```bash

```

### 方法2：自定义配置

编辑 `NSGAIITaguchiExperimentRunner.java`：

```java
// ==================== 实验配置 ====================

/** 是否启用多线程 */
private static final boolean ENABLE_MULTI_THREAD = true;  // true=多线程, false=单线程

/** 线程池大小（0表示自动检测CPU核心数） */
private static final int THREAD_POOL_SIZE = 0;  // 0=自动, 或指定如4、8等
```

#### 配置说明

**ENABLE_MULTI_THREAD**:
- `true`: 启用多线程（推荐）
- `false`: 使用单线程（用于调试或对比）

**THREAD_POOL_SIZE**:
- `0`: 自动检测CPU核心数（推荐）
- `4`: 固定使用4个线程
- `8`: 固定使用8个线程
- 等等...

#### 推荐配置

```java
// 小规模算例（J20）- 可以用更多线程
THREAD_POOL_SIZE = 0;  // 自动使用所有核心

// 大规模算例（J100）- 建议限制线程数
THREAD_POOL_SIZE = 4;  // 避免内存压力
```

## 🔍 技术实现

### 核心架构

```
┌─────────────────────────────────────────────────────────────┐
│  主线程                                                       │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│  1. 创建线程池 (ExecutorService)                             │
│  2. 提交90个任务到线程池                                     │
│  3. 等待所有任务完成                                         │
│  4. 收集结果                                                 │
│                                                               │
└─────────────────────────────────────────────────────────────┘
                            │
                ┌───────────┼───────────┐
                ↓           ↓           ↓
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ 工作线程1 │ │ 工作线程2 │ │ 工作线程N │
        ├──────────┤ ├──────────┤ ├──────────┤
        │ 任务1    │ │ 任务2    │ │ 任务N    │
        │ 任务N+1  │ │ 任务N+2  │ │ 任务2N   │
        │ ...      │ │ ...      │ │ ...      │
        └──────────┘ └──────────┘ └──────────┘
```

### 关键代码

```java
/**
 * 多线程运行所有实验
 */
private static void runAllExperimentsMultiThread(...) {
    // 1. 创建线程池
    int threadCount = Runtime.getRuntime().availableProcessors();
    ExecutorService executor = Executors.newFixedThreadPool(threadCount);
    
    // 2. 任务计数器（线程安全）
    AtomicInteger completedTasks = new AtomicInteger(0);
    
    // 3. 提交所有任务
    List<Future<Result>> futures = new ArrayList<>();
    for (实验组1-9) {
        for (运行1-10) {
            ExperimentTask task = new ExperimentTask(...);
            futures.add(executor.submit(task));
        }
    }
    
    // 4. 等待完成并收集结果
    for (Future<Result> future : futures) {
        Result result = future.get();  // 阻塞等待
        results.put(result.key, result);
    }
    
    // 5. 关闭线程池
    executor.shutdown();
}
```

### 单个任务封装

```java
class ExperimentTask implements Callable<Result> {
    @Override
    public Result call() {
        // 1. 创建NSGA-II实例
        NSGAII nsgaii = new NSGAII(problem, objectives);
        
        // 2. 设置参数
        nsgaii.setPopulationSize(config[0]);
        nsgaii.setCrossoverRate(config[1] / 100.0);
        // ...
        
        // 3. 运行算法
        List<MOIndividual> paretoFront = nsgaii.solve();
        
        // 4. 更新进度（线程安全）
        int completed = completedTasks.incrementAndGet();
        System.out.printf("进度: [%d/%d] ...", completed, totalTasks);
        
        // 5. 返回结果
        return new Result(paretoFront, runTime);
    }
}
```

## ⚙️ 线程安全设计

### 1. 任务独立性

每个实验任务完全独立，使用独立的：
- NSGAII实例
- Problem实例（深拷贝）
- 随机数种子

```java
// 每个任务独立的随机种子
nsgaii.setSeed(System.currentTimeMillis() + runNo * 1000);
```

### 2. 结果收集

使用线程安全的数据结构：

```java
// 使用ConcurrentHashMap存储结果
ConcurrentHashMap<String, Result> results = new ConcurrentHashMap<>();

// 任务完成后存储
results.put("exp1_run1", result);
```

### 3. 进度显示

使用原子计数器和同步输出：

```java
// 原子计数器
AtomicInteger completedTasks = new AtomicInteger(0);

// 线程安全的进度显示
synchronized (System.out) {
    System.out.printf("进度: [%d/%d] ...", completed, total);
}
```

## 💡 使用建议

### 何时使用多线程

✅ **推荐使用**：
- 正式的田口实验
- 需要运行多组参数
- 有多核CPU（≥4核）
- 内存充足（≥8GB）

⚠️ **不推荐**：
- 调试代码时
- CPU核心数≤2
- 内存不足（<4GB）
- 需要逐步观察过程

### 线程数配置建议

| 场景 | 推荐配置 | 原因 |
|------|---------|------|
| 小算例(J20) | 自动(0) | 充分利用CPU |
| 中算例(J50) | 自动(0)或CPU核心数 | 平衡性能 |
| 大算例(J100) | CPU核心数/2 | 避免内存压力 |
| 调试 | 单线程 | 便于追踪错误 |

### 内存考虑

每个线程会占用内存：

```
单个NSGA-II实例内存 ≈ popSize × 染色体大小 × 2

示例（J50, popSize=100）:
- 单线程: ~200MB
- 8线程: ~1.6GB
- 12线程: ~2.4GB

建议：
- 8GB内存: 最多8线程
- 16GB内存: 可以12线程
- 32GB内存: 可以16线程+
```

## 🐛 故障排查

### 问题1：OutOfMemoryError

**原因**：线程数太多，内存不足

**解决**：
```java
// 减少线程数
private static final int THREAD_POOL_SIZE = 4;  // 改为4

// 或减少种群规模
private static final int MAX_GENERATIONS = 300;  // 减少代数
```

### 问题2：CPU占用率不高

**原因**：线程数太少

**解决**：
```java
// 使用更多线程
private static final int THREAD_POOL_SIZE = 0;  // 自动检测

// 或手动增加
private static final int THREAD_POOL_SIZE = 12;
```

### 问题3：进度卡住不动

**原因**：某个任务出错或卡死

**检查**：
- 查看控制台是否有异常信息
- 检查内存是否充足
- 尝试减少线程数

## 🔄 单线程 vs 多线程

### 单线程模式

**优点**：
- ✅ 输出清晰，易于观察
- ✅ 便于调试
- ✅ 内存占用小

**缺点**：
- ❌ 运行时间长
- ❌ CPU利用率低

**适用场景**：
- 调试代码
- 观察算法行为
- 资源受限环境

### 多线程模式

**优点**：
- ✅ 运行时间短（6-10倍加速）
- ✅ CPU利用率高
- ✅ 适合大批量实验

**缺点**：
- ❌ 输出混杂（进度条形式）
- ❌ 调试困难
- ❌ 内存占用大

**适用场景**：
- 正式实验
- 参数调优
- 多核CPU环境

## 🎯 最佳实践

### 1. 首次运行

```

2. 运行1组×1次，验证输出
3. 切换到多线程模式

```

### 2. 正式实验

```
1. 启用多线程（ENABLE_MULTI_THREAD = true）
2. 自动检测线程数（THREAD_POOL_SIZE = 0）
3. 监控CPU和内存使用情况
4. 如有问题，减少线程数
```

### 3. 性能调优

```
1. 记录不同线程数的运行时间
2. 找出最佳线程数（通常=CPU核心数）
3. 平衡运行时间和资源占用
4. 固定使用最佳配置
```
