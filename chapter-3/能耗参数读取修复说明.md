# 能耗参数读取修复说明

## 问题描述

之前的实现中，`Input.java`直接跳过能耗参数行（第4-6行），导致这些数据丢失，无法在后续使用。

## 解决方案

采用**分层读取与解析**的架构：

### 1. Input.java (基础读取层)
**职责：** 读取算例文件的原始内容，包括能耗参数字符串

**修改：**
```java
// 读取并存储能耗参数原始字符串
String printerEnergyLine = reader.readLine();
input.setPrinterEnergyParams(printerEnergyLine.trim());

String batchEnergyLine = reader.readLine();
input.setBatchEnergyParams(batchEnergyLine.trim());

String discreteEnergyLine = reader.readLine();
input.setDiscreteEnergyParams(discreteEnergyLine.trim());
```

**优点：**
- 保留原始数据，不丢失信息
- 向后兼容（如果某行为空，只是存储空字符串）
- 不负责解析，职责单一

### 2. Problem.java (数据容器层)
**职责：** 存储问题的所有数据，包括能耗参数原始字符串

**新增字段：**
```java
private String printerEnergyParams;   // 打印机能耗参数（原始字符串）
private String batchEnergyParams;     // 批处理机能耗参数（原始字符串）
private String discreteEnergyParams;  // 离散机能耗参数（原始字符串）
```

**新增方法：**
- `getPrinterEnergyParams()` / `setPrinterEnergyParams()`
- `getBatchEnergyParams()` / `setBatchEnergyParams()`
- `getDiscreteEnergyParams()` / `setDiscreteEnergyParams()`
- `hasEnergyParams()` - 检查是否包含能耗参数

### 3. EnergyAwareInput.java (能耗解析层)
**职责：** 解析能耗参数字符串，创建`PowerParameters`对象，设置到`Machine`对象

**修改逻辑：**
```java
@Override
public Problem getProblemDesFromFile() {
    // 1. 调用父类读取基本信息（包括能耗参数字符串）
    Problem problem = super.getProblemDesFromFile();
    
    // 2. 检查是否有能耗参数
    if (problem.hasEnergyParams()) {
        // 从Problem对象中解析能耗参数
        parseEnergyParametersFromProblem(problem);
        // 应用到Machine对象
        applyEnergyParametersToMachines(problem);
    } else {
        // 使用默认参数
        initializeDefaultEnergyParams(problem);
        applyEnergyParametersToMachines(problem);
    }
    
    return problem;
}
```

**新增方法：**
- `parseEnergyParametersFromProblem()` - 从Problem对象解析能耗参数
- `parseAndStoreMachineTypeEnergy()` - 解析单类机器的能耗参数

**删除方法：**
- `readEnergyParameters()` - 不再重新打开文件读取
- `readMachineTypeEnergyParams()` - 被`parseAndStoreMachineTypeEnergy()`替代

### 4. Machine.java (机器实体层)
**职责：** 存储机器的能耗参数对象

**已有字段：**
```java
public PowerParameters powerParams;  // 能耗参数对象
```

**已有方法：**
- `setPowerParameters()` - 设置能耗参数
- `getPowerParameters()` - 获取能耗参数
- `hasPowerParameters()` - 检查是否已配置

## 数据流程

```
算例文件 (*.txt)
    ↓
Input.getProblemDesFromFile()
    ├─ 读取第1-3行（机器配置）
    ├─ 读取第4-6行（能耗参数字符串）→ 存入Problem对象
    └─ 读取工件信息
    ↓
Problem对象
    ├─ printerEnergyParams: "2 1 4.20 1.50 7.50 180 1 2 3.80 ..."
    ├─ batchEnergyParams:   "1 1 4.50 1.70 8.20 220 1"
    └─ discreteEnergyParams: "2 1 3.60 1.40 7.00 150 1 2 4.10 ..."
    ↓
EnergyAwareInput.getProblemDesFromFile()
    ├─ 调用super() → 获取Problem对象
    ├─ 检查problem.hasEnergyParams()
    ├─ 解析能耗参数字符串 → PowerParameters对象
    └─ 设置到Machine对象
    ↓
Machine对象
    └─ powerParams: PowerParameters(P_run, P_idle, E_switch, ...)
```

## 关键优势

1. **不丢失数据**：能耗参数被完整保存在Problem对象中
2. **职责分离**：
   - Input负责读取
   - Problem负责存储
   - EnergyAwareInput负责解析
   - Machine负责使用
3. **向后兼容**：旧算例（无能耗参数）会使用默认值
4. **可扩展**：未来可以添加其他参数而不影响现有逻辑

## 能耗参数格式

```
机器数量 [机器ID P_run P_idle E_switch T_warmup allowSwitch] ...
```

**参数说明：**
- `机器ID`：1-based编号
- `P_run`：运行功率 (kW)
- `P_idle`：空载功率 (kW)
- `E_switch`：开关机能耗 (kWh)
- `T_warmup`：预热时间 (秒)
- `allowSwitch`：是否允许关机 (0/1)

**示例：**
```
2 1 4.20 1.50 7.50 180 1 2 3.80 1.30 6.80 200 1
```
表示2台打印机：
- 机器1: P_run=4.20kW, P_idle=1.50kW, E_switch=7.50kWh, T_warmup=180s, 允许关机
- 机器2: P_run=3.80kW, P_idle=1.30kW, E_switch=6.80kWh, T_warmup=200s, 允许关机

## 后续使用

在算法中使用能耗参数：

```java
// 使用EnergyAwareInput读取
EnergyAwareInput input = new EnergyAwareInput(file);
Problem problem = input.getProblemDesFromFile();

// 获取机器的能耗参数
Machine[] machines = problem.getMachines();
PowerParameters params = machines[0].getPowerParameters();

// 使用EnergyCalculator计算能耗
EnergyCalculator calculator = new EnergyCalculator(params);
double energy = calculator.calculateEnergy(schedule);
```
