## 📖 程序简介

**NSGAIIRunner.java** 是一个完整的NSGA-II多目标优化主程序，用于解决绿色车间调度问题。

### 主要功能

✅ **多目标优化**
- 目标1: Cmax (最大完工时间) - 最小化
- 目标2: Energy (总能耗，智能开关机) - 最小化

✅ **灵活的算例加载**
- 支持命令行参数
- 支持交互式选择
- 自动处理能耗参数

✅ **完整的结果输出**
- 控制台实时显示
- 自动保存到文件
- 能耗策略对比分析

## 🚀 使用方法

### 方法1: 交互式运行（推荐）

直接运行程序，按提示选择算例：

```bash
# 在IDEA中运行
右键点击 NSGAIIRunner.java -> Run 'NSGAIIRunner.main()'
```

程序会提示：
```
请选择算例文件:
1. 使用默认算例 (chapter-2 J20P3B2D5_01.txt)
2. 输入自定义路径

请选择 (1/2): 
```

### 方法2: 命令行指定算例

```bash
# 使用绝对路径
java AlgorithmFrame.nsgaii.NSGAIIRunner "C:/path/to/instance.txt"

# 使用相对路径
java AlgorithmFrame.nsgaii.NSGAIIRunner "../chapter-2/src/main/resources/instance/J20/J20P3B2D5_01.txt"
```

### 方法3: 在代码中修改

修改 `NSGAIIRunner.java` 中的 `getInstancePath()` 方法：

```java
private static String getInstancePath(String[] args) {
    // 直接返回你的算例路径
    return "your/instance/path.txt";
}
```

## ⚙️ 配置参数

在 `NSGAIIRunner.java` 文件顶部修改配置：

### 算法参数

```java
private static final int POPULATION_SIZE = 100;        // 种群规模
private static final int MAX_GENERATIONS = 200;        // 最大代数
private static final double CROSSOVER_RATE = 0.9;      // 交叉率
private static final double MUTATION_RATE = 0.1;       // 变异率
private static final double MAX_RUN_TIME = 10.0;       // 最大运行时间（分钟）
```

**参数建议：**

| 算例规模 | 种群规模 | 最大代数 | 运行时间 |
|---------|---------|---------|---------|
| 小型 (10-20工件) | 50-100 | 100-200 | 5-10分钟 |
| 中型 (20-50工件) | 100-200 | 200-500 | 10-30分钟 |
| 大型 (50+工件) | 200-500 | 500-1000 | 30-60分钟 |

### 输出配置

```java
private static final boolean SAVE_RESULTS = true;      // 是否保存结果
private static final boolean SHOW_PROGRESS = true;     // 是否显示进度
private static final int DISPLAY_TOP_N = 20;           // 显示前N个解
```

### 随机种子

```java
private static final long RANDOM_SEED = 0;  // 0=随机，其他值=固定种子
```

**用途：**
- `RANDOM_SEED = 0`: 每次运行结果不同（用于正常实验）
- `RANDOM_SEED = 42`: 每次运行结果相同（用于调试或对比实验）

### 结果解读

**Pareto前沿中的每个解：**

| 列名 | 说明 |
|-----|------|
| Cmax | 最大完工时间（越小越好） |
| 能耗 | 总能耗，包含智能开关机策略（越小越好） |
| PackingQ | 打印平台利用率（0-1，越大越好） |
| 批次数 | 批处理批次数（越少越好） |
| 拥挤距离 | NSGA-II多样性指标（INF表示边界解） |

**如何选择解决方案？**

1. **重视时间**: 选择Cmax最小的解（第1个）
2. **重视能耗**: 选择能耗最小的解（最后几个）
3. **平衡方案**: 选择中间的解，时间和能耗都较好
4. **决策者偏好**: 根据实际生产需求权衡

## 🔧 常见问题

### Q1: 找不到算例文件？

**错误信息：**
```
算例文件不存在: xxx.txt
```

**解决方案：**
1. 检查文件路径是否正确
2. 使用绝对路径
3. 确保算例文件存在
4. 如果没有算例，运行 `InstanceGenerator` 生成

### Q2: 程序运行很慢？

**可能原因：**
- 算例规模太大
- 种群规模或代数设置过大
- 没有达到终止条件

**解决方案：**
1. 减小 `POPULATION_SIZE` 和 `MAX_GENERATIONS`
2. 设置合理的 `MAX_RUN_TIME`
3. 对于大规模问题，建议：
   - 种群规模：200-300
   - 最大代数：500-1000
   - 运行时间：30-60分钟

### Q3: Pareto前沿规模太小？

**可能原因：**
- 种群多样性不足
- 进化代数不够

**解决方案：**
1. 增加种群规模
2. 增加最大代数
3. 调整变异率（适当增大到0.15-0.2）

### Q4: 能耗策略未节能？

**显示：**
```
⚠️ 当前调度下开关机策略未节能
原因: 可能空闲时间过短
```

**说明：**
这是正常情况。当机器空闲时间很短时，开关机消耗的能量可能大于待机消耗，此时保持待机更节能。这正是智能开关机策略的优势——只在有利可图时关机。

### Q5: 如何对比不同参数的影响？

**方法：**
1. 设置固定随机种子（如 `RANDOM_SEED = 42`）
2. 只修改一个参数
3. 运行并保存结果
4. 对比不同参数下的结果文件

## 📝 修改建议

### 添加更多目标函数

在 `configureObjectives()` 方法中添加：

```java
// 目标3: 总拖期
objectives.add(new MOEvaluator.TotalTardiness(problem, dueDate));

// 目标4: 批处理等待时间
objectives.add(new MOEvaluator.TotalBatchWaitingTime());
```

### 修改能耗策略

```java
// 关闭开关机策略（纯待机模式）
MOEvaluator.TotalEnergyConsumption energyObj = 
    new MOEvaluator.TotalEnergyConsumption(problem, false, false);

// 启用更激进的开关机策略
MOEvaluator.TotalEnergyConsumption energyObj = 
    new MOEvaluator.TotalEnergyConsumption(problem, true, true);
```

### 批量运行多个算例

```java

    };
    
    for (String path : instances) {
        System.out.println("运行算例: " + path);
```
