# NSGA-II 田口实验 - 参数说明

## 📊 实验设计更新

### 因子D的变更

原设计: **局部搜索间隔 (localSearchInterval)**
- 含义：每隔多少代执行一次局部搜索
- 水平：5代、10代、15代

**新设计: 每代搜索次数L (localSearchL)**
- 含义：每个精英个体的局部搜索尝试次数
- 水平：5次、10次、20次
- **局部搜索每代都执行** (interval=1)

## 🔧 局部搜索配置详解

### 固定参数（所有实验组相同）

```java
interval = 1           // 每代都执行局部搜索
eta = 0.10            // 精英比例：选择10%的个体
epsE = 0.05           // T型算子允许能耗上升5%
epsC = 0.02           // E型算子允许Cmax上升2%
improvC = 0.005       // T型算子要求Cmax下降0.5%
improvE = 0.01        // E型算子要求能耗下降1%
```

### 变化参数（田口实验因子）

```java
L = {5, 10, 20}       // 因子D：每个精英的尝试次数
```

## 💡 参数含义说明

### L - 每个精英的尝试次数

**定义**: 对每个精英个体，执行多少次局部搜索尝试

**工作流程**:
```
每一代:
  1. 选择精英个体（种群的10%）
  2. 对每个精英:
     - 尝试 L 次局部搜索
     - 每次随机选择一个邻域算子
     - 如果改进则接受新解
  3. 将改进后的精英加入种群
  4. 环境选择保持种群规模
```

**示例**（popSize=100, eta=0.10）:
- 精英数量 = 100 × 0.10 = 10 个
- 若 L=5，每代总尝试次数 = 10 × 5 = 50 次
- 若 L=10，每代总尝试次数 = 10 × 10 = 100 次
- 若 L=20，每代总尝试次数 = 10 × 20 = 200 次

### interval - 局部搜索间隔

**当前设置**: interval = 1（固定值）

**含义**: 每隔多少代执行一次局部搜索
- interval = 1：每代都执行
- interval = 5：每5代执行一次
- interval = 10：每10代执行一次

**当前策略**: 为了充分利用局部搜索，设置为每代都执行

## 📈 计算复杂度分析

### 每代局部搜索成本

```
总尝试次数 = 精英数量 × L
精英数量 = popSize × eta

例如：
- popSize=50, eta=0.10, L=5  → 总尝试 = 5 × 5 = 25 次
- popSize=100, eta=0.10, L=10 → 总尝试 = 10 × 10 = 100 次
- popSize=150, eta=0.10, L=20 → 总尝试 = 15 × 20 = 300 次
```

### L值的影响

**L=5（保守）**:
- 优点：计算快速，适合大规模问题
- 缺点：可能错过较深的局部最优

**L=10（平衡）**:
- 优点：计算成本和搜索深度平衡
- 推荐：大多数问题的默认选择

**L=20（激进）**:
- 优点：更深入的局部搜索，可能找到更好的解
- 缺点：计算耗时增加，可能过度优化

## 🔍 因子效应预测

### 预期影响排序

根据多目标优化经验，预期各因子对HV的影响：

1. **A (popSize)** - 影响最大
   - 更大的种群 → 更好的多样性 → 更大的HV
   - 但过大会降低收敛速度

2. **D (localSearchL)** - 影响较大
   - 更多的局部搜索 → 更好的收敛性 → 更大的HV
   - 但有边际效应递减

3. **B (crossoverRate)** - 影响中等
   - 平衡探索和利用
   - 0.80-0.90通常较优

4. **C (mutationRate)** - 影响较小
   - 主要维持多样性
   - 过高会破坏已有好解

## 🎯 使用建议

### 针对不同规模问题

**小规模（J20）**:
- 推荐: popSize=50-100, L=10-20
- 原因: 问题简单，可以用较大的L深入搜索

**中规模（J50）**:
- 推荐: popSize=100-150, L=10-15
- 原因: 平衡搜索质量和计算成本

**大规模（J100）**:
- 推荐: popSize=150-200, L=5-10
- 原因: 问题复杂，需要更大种群但控制L值

### 针对不同目标

**重视HV最大化**:
- 选择较大的popSize和L
- 接受较长的运行时间

**重视计算效率**:
- 选择中等的popSize和较小的L
- 在合理时间内获得较好的解
